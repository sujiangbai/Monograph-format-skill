# format-monograph V0.2.2：有效格式与复杂结构加固

## 背景与目标

V0.2.1 已建立“盘点 -> 结构映射 QA -> 格式应用 -> 审计”的基本链路，并验证了真实 Word `TOC` 字段、标题映射、内容指纹及受保护对象审计。真实教材单章的结构模式试运行同时表明：仅修改样式定义并检查样式本身，不能保证段落最终显示格式正确；章节摘录的起始章号、表内题注、非数据表格、字体别名和复杂尾部分节也需要更精确的控制。

V0.2.2 的目标是让 Skill 依据经批准的语义对象修改“实际生效格式”，并使单章试排与整书一次性处理共享同一套安全机制。核心继续遵循开放 Agent Skills 规范，使用跨平台 Python 和 OOXML，不依赖 Word COM、Agent 私有 API 或特定平台提示。

本方案只保存可公开的通用规则、接口和合成测试要求。真实书稿、段落文字、图片、目录、题注、页码、对象、哈希、统计、路径、试排文件、渲染页和任务报告不得提交仓库。

## 不变的最高约束

1. 每次调用 Skill 时，当前调用者明确提出并确认的格式要求具有最高优先级；出版社要求、国家标准、模板和样书按已确认顺序作为补充依据。
2. 最高优先级要求与其他依据冲突时必须报告冲突及影响；在调用者作出决定前不得静默选择。
3. 原始 DOCX 永不覆盖。正文、表格文字、脚注、尾注、引用、答案、批注和对象内容不得改写，只有已批准的派生字段可以变化。
4. 独立成行或复杂公式必须保持为可编辑的 OMML、MathType/OLE，或经验证由 LaTeX 转换为 OMML；不得把公式转成图片。既有公式对象不得擅自互转。
5. 无法可靠识别、资料未覆盖或未获批准的对象保持原状并进入 QA 报告。
6. 缺少渲染器时只能进入结构模式；不得声称完成视觉验收或最终交付。

## 结构映射 1.1

结构映射 schema 升级为 `1.1`，读取端继续兼容 `1.0`。1.1 增加以下来源绑定信息；映射仍只保存定位、角色、设置和哈希，不保存书稿文字。

### 语义段落角色

增加 `paragraph_roles`，至少支持：

- `title`、`front_matter`、`body`、`heading_1` 至 `heading_4`。
- `figure_caption`、`table_caption`、`equation_caption`。
- `long_quote`、`reference_entry`、`answer`、`teaching_callout`。
- `unknown`，只报告，不自动格式化。

每项使用有类型的定位器和文本 SHA-256 绑定源文件。V0.2.2 至少支持：

- `body_paragraph`：正文段落索引。
- `table_cell_paragraph`：表格、行、单元格和单元格内段落索引。

页眉、页脚、脚注、尾注和文本框的定位器只有在可稳定验证时才可增加；不支持的范围保持原状并报告。

任何依赖语义角色的格式规则都必须有获批结构映射。不得把所有 `Normal` 样式段落默认视为正文，也不得因修改正文样式而改变书名页、版权页或目录前置文字。

### 编号上下文

增加 `numbering` 块，记录：

- 经识别和批准的 `chapter_start`。
- 标题层级、编号语法和预期递进关系。
- 单章摘录或整书模式。
- 缺号、跳号、重复号和层级不一致等异常。
- 是否批准移除原手工编号并改用多级列表。

应用前先解析并验证原手工前缀，再建立与 Heading 1-4 关联的多级列表。单章摘录必须使用批准的起始章号；整书必须连续验证全书章、节层级。只有在新编号结构已经建立且前缀可唯一识别时，才可移除手工编号。

### 题注

题注支持正文段落与表格单元格段落定位，并记录标签、层级、局部顺序、完整性和层级一致性。

- 可唯一解释且获批的题注迁移为真实 `SEQ` 字段，并建立供 `REF`/`PAGEREF` 使用的书签。
- 位于合并表格首行的表题，可在逐项获批后迁移为表格上方独立 `Caption` 段落，并删除已确认仅承载表题的原行。
- 题注不完整、编号层级不一致、说明文字边界不清或引用目标不唯一时，只报告并阻塞该项迁移，不猜测或自动改号。

### 表格角色

每个表格增加 `kind`：`data`、`layout`、`callout` 或 `unknown`，并可记录：

- `caption_row`。
- `header_rows` 与 `repeat_header_rows`。
- `prevent_normal_row_split`。
- 超高行、合并单元格、跨页和横向分节候选。
- 题注行迁移是否获批。

只有获批的 `data` 表才应用数据表规则。布局表、图片容器、教学提示框和未知表格不得套用通用表格正文、重复表头或禁止拆行规则。允许连续多行表头重复；普通数据行禁止跨页拆分，超高行保留拆分并报告。

### 尾部分节

尾部空白页和分节候选必须显式报告：

- 可见正文、表格、图片、公式、文本框和嵌入对象。
- 书签、批注、脚注、尾注和交叉引用锚点。
- 页眉页脚引用及其是否含内容。
- 页码起始、首页不同、奇偶页不同、纸张、方向、边距和分节类型。

候选生成不得仅因末尾无正文就标为可安全删除。删除必须逐项获批；只移除已确认无用的边界或部件，保持前一有效分节、页码连续及必要的页眉页脚关系。存在可见内容或用途不明的独立设置时阻塞。

## 格式应用

### 属性范围内清理直接格式

对每条获批规则，先确定该规则控制的属性，再只对获批目标清理相冲突的直接格式，随后应用目标样式或属性。控制范围至少包括：

- 中西文字体、字号、字重和斜体。
- 对齐、行距、段前后距、缩进。
- 与标题相关的段前分页、与下段同页和段中不分页。

未被规则控制的强调、颜色、语言、字符样式、上下标、隐藏文字、超链接、字段、书签、批注和修订信息必须保留。清理不得扩展到未获批段落、未知表格或对象内部。

### 标准样式补全

当获批规则需要 `Caption`、`Quote` 或其他目标样式，而源文档缺少该样式时，Skill 必须根据配置确定性创建样式并设置稳定的样式 ID、类型和继承关系。不得依赖 Word 界面语言中的显示名称，也不得因内置样式缺失而中断已获批任务。

### 字体别名

环境检测与配置验证增加字体规范化层。至少识别同一物理字体家族的常见中英文名称，例如宋体与 SimSun、黑体与 SimHei，并结合可用的系统字体注册信息或字体元数据报告规范家族和来源。

已验证的别名匹配不属于字体替换；真实缺失字体仍必须阻塞或进入 QA。不得因名称不同静默选择近似字体。

### 渲染器发现

以下命令增加可选渲染器路径：

```text
check_environment.py --json [--renderer <path>]
render_docx.py <input.docx> --output-dir <directory> [--renderer <path>]
```

也可读取 `FORMAT_MONOGRAPH_RENDERER` 环境变量。报告必须区分自动发现、显式参数和环境变量来源，并验证可执行文件及转换结果。Skill 不自动安装渲染器；无法渲染时继续按能力分级降级。

## 有效格式审计

`audit_docx.py` 扩展为按“样式继承 + 段落直接格式 + 运行直接格式”解析获批目标的实际生效值，而不是只检查样式定义。

对每个获批角色至少审计：

- 中西文字体、字号、粗体/斜体。
- 对齐、行距、段前后距和缩进。
- 标题分页与保持属性。
- 是否仍存在覆盖受控属性的直接格式。

任一受控属性实际值不符合规则，或存在导致显示结果偏离的直接格式覆盖，审计必须失败。审计报告只保存角色、定位、规则 ID、期望值、实际值和失败原因，不复制书稿文字。

同时审计：

- 标题编号定义、起始章号、层级关联和预期递进。
- `TOC`、`SEQ`、`REF`、`PAGEREF`、`PAGE` 字段指令及必要书签。
- 表题位置、批准的重复表头行和行拆分设置。
- 目标样式存在性及其确定性定义。
- 内容指纹、媒体、嵌入对象和 OMML 哈希。
- 审计报告中的派生字段规范化标志必须反映结构映射和配置两条实际路径，不能出现“已排除”但实际未执行的误报。

字段缓存值不能作为唯一通过依据；无法在当前环境更新字段时必须报告待 Word 或等效软件刷新。

## 命令接口

保持 V0.2.1 命令兼容，并使用同一份获批结构映射贯穿应用与审计：

```text
inspect_docx.py <input.docx> --output <inventory.json> --structure-map-output <candidate.json>
validate_structure_map.py <structure-map.json> --source <input.docx>
apply_profile.py <input.docx> --profile <profile.json> --structure-map <approved.json> --output-dir <directory>
audit_docx.py <original.docx> <formatted.docx> --profile <profile.json> --structure-map <approved.json> --output <audit.json>
```

结构映射 1.0 可继续读取，但只有 1.1 才能授权语义角色、非首行表头、表内题注迁移、章节起始号和扩展尾节删除。缺少这些信息时保持原状并生成 QA，不以旧版默认值代替。

## 测试与验收

所有仓库测试使用完全合成的 DOCX，至少覆盖：

1. 单章从非首章开始及整书从首章开始，验证标题编号起始、层级递进和不意外重启。
2. 正文与二至四级标题含冲突直接格式，验证只清理受控属性；未获批的书名页 `Normal` 段落保持不变。
3. 合并首行承载表题、第二行或连续多行为表头；获批后表题迁移到表上方，正确重复表头，布局表和教学框保持不变。
4. 不完整题注、层级不一致题注和断链引用仅报告。
5. 缺少 `Caption` 等目标样式时可按配置确定性创建。
6. Windows 字体注册名及 macOS/Linux 字体元数据的别名匹配；真正缺失字体仍阻塞。
7. 尾部空分节分别包含空引用、非空页眉页脚、页码重启、独立纸张设置或锚点时，候选证据和删除结果正确。
8. 真实 `TOC` 只替换获批静态目录范围，范围外前置文字不被正文规则修改。
9. OMML、MathType/OLE、旧公式对象和媒体哈希保持一致；公式图片候选阻塞。没有真实可编辑公式样例时不得宣称公式流程通过。
10. 脚注、尾注、批注、书签、超链接、文本框、修订和字段在格式处理后保持完整。
11. 修改前的有效格式审计能够发现直接格式覆盖，修改后才通过；派生字段规范化标志与实际路径一致。
12. 缺少渲染器时明确进入结构模式；存在显式渲染器时逐页渲染干净稿与审阅稿。
13. 在 Windows、macOS、Linux 和支持的 Python 版本运行核心测试，并继续执行 LibreOffice 渲染冒烟测试与 `skills-ref validate`。

真实书稿仅在用户本地复测。单章必须完成内容审计、对象审计和逐页视觉 QA 后，才进入整书一次性试排；整书最终验收必须逐页覆盖，不能由单章或抽样替代。

## 实施顺序与治理

1. 从最新 `main` 创建 `plan/v0.2.2-effective-format-hardening`，新增本方案并更新方案索引。
2. 方案 PR 完成 QA 并取得用户明确授权后，以 squash merge 合并。
3. 从新的 `main` 创建 `skill/effective-format-v0.2.2`，先实现结构映射 1.1、1.0 兼容和合成夹具。
4. 实现语义角色定位、属性范围内直接格式清理、标准样式补全及有效格式审计。
5. 实现编号起始、复杂题注/表头、尾部分节证据、字体别名和渲染器覆盖。
6. 完成跨平台 CI、内容与对象保护、Agent Skills 规范检查，并进行独立上下文前向测试。
7. 实现 PR 经 QA 和用户明确授权后才能合并。
8. 使用合并后的 Skill 在本地重新执行单章完整渲染验收；通过后再执行整书一次性端到端验收。

任何实施中出现的新方案变化必须新增更高版本方案文件，不得覆盖本文件。
