# format-monograph V0.3.2：Word 字段结果选择性回写

## 背景与结论

V0.3.1 私密单章复测确认书名居中和标题缩进修复有效，同时暴露了字段终稿化的安全缺口：

1. Skill 生成的基准 DOCX 已完成受控排版和内容审计。
2. Microsoft Word 在临时副本中能够正确更新目录、页码及引用字段。
3. Word 保存时会同时重序列化段落、运行、表格和分节等 OOXML；当前实现即使只想保留字段缓存，仍需要验证并替换整个 XML 部件。
4. 因此安全门禁会拒绝包含非字段差异的 Word 临时副本，终稿只能降级为字段待更新，无法可靠进入 `final_ready`。

V0.3.2 将 Word 或经批准的等效软件限定为“字段计算与目标软件分页后端”。后端临时稿永远不直接成为交付稿；核心 Python 逻辑只把通过验证的字段结果写回基准 DOCX，其他后端改写全部丢弃。

本版本不改变正文、标题文字、图表位置、公式对象、人工图表编号或已批准的格式规则。

## 安全边界

- 基准 DOCX 是唯一回写母本；输出从基准包复制生成，不以 Word 保存后的包为基础。
- 允许回写的范围仅包括任务批准且可唯一匹配的字段结果、对应字段状态标志，以及完成字段终稿所必需的确定性设置。
- 默认支持：
  - `TOC`：批准目录范围内的目录结果；
  - `PAGE`、`NUMPAGES`、`SECTIONPAGES`：页码类标量结果；
  - `PAGEREF`：经批准书签对应的页码结果；
  - `REF`：经批准书签对应且可验证的引用结果；
  - 已存在并经任务批准的其他派生字段。
- 不因本版本自动创建或转换图表题注 `SEQ`；人工图号和表号继续保持。原稿已有 `SEQ` 只有在结构映射明确批准时才允许刷新。
- 域外字段、嵌套或损坏字段、共享作者内容边界的字段、无法唯一匹配的重复字段均不得猜测，必须保持基准结果并进入阻塞 QA 或 `deferred`。
- 后端临时稿中的正文、样式、编号、分节、页眉页脚结构、表格、图片、OMML、MathType/OLE、媒体、书签、关系和自定义 XML 不得整体回写。
- 后端如果改变可见作者内容、字段指令、书签目标、受保护对象或影响分页的批准结构，字段结果视为不可信并整体拒绝。
- 正式书稿、字段显示文字、目录条目、本地路径、临时稿和渲染页不得进入仓库、CI 日志或公开工件。

## 字段清单与匹配

- 在调用后端前生成本地字段清单，使用哈希和计数而非书稿文字记录：
  - OOXML 部件；
  - 字段类型与规范化指令哈希；
  - 简单字段或复杂字段形式；
  - 结构作用域、书签目标和稳定邻接锚点；
  - 同类型字段序号及嵌套关系；
  - 是否获得任务批准。
- 将字段解析为明确的开始、指令、分隔、结果和结束边界；禁止使用仅按文本搜索或全局序号替换的方式。
- 基准字段与后端字段必须一一匹配。匹配依据依次为部件、字段类型、规范化指令、批准作用域、书签目标和稳定锚点；任何多义匹配均停止该字段。
- 字段指令及边界由基准稿保留，不从后端覆盖。
- 标量字段只回写结果值；字体、字号、字重、对齐和运行属性继续使用基准稿已批准格式。
- `REF` 结果必须与批准书签内容或其允许的字段开关语义一致；无法验证的富文本引用保持原状并报告。
- 字段回写采用事务方式：任一关键字段失败时不产生半完成终稿，也不覆盖已有候选稿。

## 目录专用处理

- `TOC` 作为批准的派生内容区域处理，不按普通单值字段处理。
- 基准稿必须具有唯一且边界完整的批准目录字段；目录边界块不得混有书名、正文、图片、表格或其他作者内容。
- 从后端提取目录结果时，验证：
  - 条目只对应批准的标题角色；
  - 标题顺序与结构映射一致；
  - 原目录已有附录时保留附录，原目录没有时不自动加入；
  - 目录页码与目标软件分页结果一致；
  - 超链接或书签仅指向文档内部批准目标；
  - 不出现外部关系、未知字段或额外作者文字。
- 通过后只替换基准目录字段的结果区域，保留基准字段指令、目录标题、分节边界和非目录内容。
- 目录验证失败时保留基准目录并将字段状态标为 `deferred`，不得用静态目录文本冒充终稿。

## 分页与后端契约

- 目录页和正文页的分节、起始页码、数字格式、奇偶页页脚、正文连续页码和书名页隐藏页码，必须在调用 Word 前由核心 Python 逻辑确定并审计。
- Word 适配层不得再创建、删除或规范化分节、页眉页脚、页码字段、分页符或目录范围；只允许：
  1. 打开一次性临时副本；
  2. 重新分页；
  3. 更新批准字段；
  4. 保存临时结果并导出视觉检查 PDF；
  5. 返回不含书稿文字的能力与计数清单。
- 后端更新前后比较内容指纹、字段指令、书签、结构角色、分页设置和受保护对象。Word 的序列化噪声可以报告后丢弃，但不能进入交付稿。
- 选择性回写后的 DOCX须再次在目标 Word 中以只读、禁止二次字段更新的方式渲染；目录页码、可见页码和页数必须与字段计算会话一致。
- LibreOffice 或其他后端可复用同一字段清单和选择性回写协议；无法满足协议时只能降级，不得宣称与 Word 等价。

## 接口与状态

保持跨 Agent 主接口不变：

```text
run_monograph.py finalize --work-dir <directory>
run_monograph.py verify --work-dir <directory>
```

内部终稿化接口增加显式策略：

```text
finalize_docx.py <input.docx> ... --field-writeback selective
finalize_docx.py <input.docx> ... --field-writeback deferred
```

- `selective` 是存在批准后端时的默认安全策略。
- `deferred` 保留字段并设置打开时更新，仅允许交付候选稿。
- 删除“验证整个 XML 部件后直接替换”的成功路径；旧参数如存在须保持兼容但映射到新策略或明确报错。
- `run-state.json` 和报告新增：
  - 后端名称、版本和能力；
  - 字段总数、批准数、匹配数、回写数、拒绝数；
  - 目录验证、分页一致性和只读复验状态；
  - 被丢弃的后端非字段差异类别及哈希；
  - `selective_verified`、`deferred` 或 `rejected` 结果；
  - 各阶段耗时和断点续跑缓存键。
- 状态只有在字段结果为 `selective_verified`、内容与对象审计通过、目标软件只读复验通过并完成逐页视觉检查后，才能进入 `final_ready`。

## 实现范围

- 将 `finalize_docx.py` 的字段比较逻辑拆为字段解析、稳定匹配、结果提取、受控补丁和补丁后审计五个步骤。
- 新增可测试的字段清单和补丁数据模型；补丁对象不得包含未批准的完整 OOXML 部件。
- 对简单字段、复杂标量字段和跨段落 `TOC` 分别实现处理器，避免一个宽泛算法承担所有字段类型。
- 修改 Microsoft Word 适配器，移除分页结构修改职责，并增加“字段更新”和“只读复验”两种明确模式。
- 将所有页码和分节结构变更集中到核心 DOCX 处理逻辑，保证跨 Agent 调用一致。
- 更新字段终稿化、运行清单、QA 与报告参考文件；保持 `SKILL.md` 简洁。
- 继续沿用 V0.3.0 断点续跑：基准稿、配置、结构映射、字段清单或后端能力未变化时可复用安全阶段；字段补丁或视觉复验失败只重跑受影响阶段。

## 测试与验收

- 合成测试覆盖简单字段、复杂字段、嵌套字段、多个相同指令、字段跨运行或段落、页眉页脚字段、断裂字段和共享作者内容边界。
- 目录测试覆盖多页目录、四级标题、附录保留策略、内部超链接、错误标题范围、重复目录和静态目录迁移。
- 模拟 Word 对 `rsid`、运行拆并、命名空间、表格网格及其他序列化结构的改写，确认这些差异不会进入输出。
- 模拟正文、字段指令、书签、分节、表格宽度、公式、OLE、媒体或关系发生实质变化，确认字段结果被拒绝。
- 验证输出包除批准字段结果和字段状态外均来自基准包；受保护对象哈希、正文指纹、图表位置和结构映射保持一致。
- 验证目录与正文分别从阿拉伯数字 1 开始，正文跨章节连续，奇偶页均显示外侧页码，书名页不显示且不计页码。
- 在 Word 2016/2019/2021/365 可用环境中至少完成一次字段更新与只读复验；未具备实机条件的版本标记待验证。
- LibreOffice 继续执行合成渲染烟测，但不得替代目标 Word 的正式字段和分页验收。
- 在四个首批 Agent 中运行相同的合成输入与清单；适配层不得改变安全边界或交付状态。
- 使用本地私密单章复现此前拦截场景，再使用私密整书验证性能、目录页码和全部页面；任何书稿内容均不得提交仓库。
- 回归测试必须覆盖 V0.3.1 的书名居中、标题零缩进及现有 86 项测试。

## 治理与发布

1. 从最新 `main` 创建 `plan/v0.3.2-selective-field-writeback`，新增本方案并更新索引，不修改 V0.3.1 或更早方案正文。
2. 方案 PR 经用户明确批准并合并后，从最新 `main` 创建 `skill/v0.3.2-selective-field-writeback`。
3. 实现 PR 完成合成测试、跨平台 CI、Word 实机字段更新、私密单章复测和私密整书复测后，单独请求合并批准。
4. 合并后再决定是否发布 `v0.3.2-rc.1`；不得移动、覆盖或伪装已有标签。
5. 若选择性回写仍不能证明安全，保持 `deferred` 并建立新方案，不得通过放宽内容保护门禁换取自动终稿。

## 已确定默认

- 当前调用者的明确格式要求仍是任务级最高格式依据，但不能突破原稿、正文、公式、对象和审计保护边界。
- Word 临时稿和 PDF 只用于本地字段计算与视觉证据，不是交付母本，也不得上传公开仓库。
- 对后端序列化差异的默认处理是“识别、报告、丢弃”，不是加入白名单后整体回写。
- 字段匹配或结果验证存在歧义时，安全降级优先于自动完成。
- V0.3.2 只解决字段终稿与分页一致性，不夹带新的教材格式规则或无关重构。
