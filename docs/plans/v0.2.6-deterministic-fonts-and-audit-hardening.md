# format-monograph V0.2.6：确定性字体、字段页脚与终稿审计加固

## 背景与目标

V0.2.5 已能在 Microsoft Word 中自动刷新目录和页码，并完成双分节页码、奇偶外侧页码及表格视觉格式。真实单章试排进一步暴露出以下问题：

1. 配置虽然明确要求正文宋体、标题黑体，但原 DOCX 的主题字体仍可能通过样式继承生效，使 Word 显示或实际使用等线、等线 Light 等未批准字体。
2. 当前报告主要记录配置字体与本机字体解析结果，没有验证每个受控对象在最终 DOCX 中的有效字体。
3. 重复执行页码设置可能累积多个 `PAGE` 字段，导致两位数以上的奇数页页码显示错误。
4. Microsoft Word COM 适配器在部分环境中对多参数 `Documents.Open` 和布尔属性赋值兼容性不足。
5. Word 保存后可能重编号页眉页脚部件；按部件路径比较会把语义相同的派生页脚误判为内容变化。
6. 真实目录展开后，旧静态目录定位器和已批准编号替换可能产生审计误报。
7. 正文按右页起排时产生的中间空白背页，不能与可删除的尾部空白页混为一类。

V0.2.6 的目标是让受控文字的最终有效字体与批准配置完全一致，让页脚字段可重复执行且不累积，并使 Word 字段终稿化后的完整性审计稳定、可解释。

## 权威规则

1. 每次调用 skill 的用户明确要求继续具有最高任务级优先级。
2. 出版社已批准要求、用户批准配置和用户批准结构映射共同决定受控对象的字体；原稿主题字体不得覆盖这些要求。
3. 未被任何批准规则覆盖的对象保持原状，不得为了统一主题而全局替换字体。
4. 缺少指定字体时继续阻塞或生成 QA，不得静默使用主题字体、近似字体或系统回退。
5. 原稿、书稿内容、试排稿、渲染页和本地路径不得进入仓库、日志、PR 描述或测试工件。

## 确定性字体模型

### 有效字体解析

新增统一的有效字体解析器，按 Word 的实际优先顺序分析：

1. 字符级直接格式 `w:rPr/w:rFonts`。
2. 字符样式。
3. 段落样式及 `basedOn` 继承链。
4. 表格样式和条件格式。
5. `docDefaults`。
6. `asciiTheme`、`hAnsiTheme`、`eastAsiaTheme`、`cstheme` 对 `theme1.xml` 的解析。
7. 在无法确定时标记为 unresolved，不得猜测系统字体回退结果。

解析结果至少分别报告 ASCII/HAnsi、East Asia 和 Complex Script 字体来源、最终字体名及是否来自主题。

### 字体应用

对批准规则命中的受控角色执行以下操作：

- 在角色对应的真实 Word 样式中显式写入 `ascii`、`hAnsi`、`eastAsia` 和 `cs` 字体。
- 删除同一 `rFonts` 上会覆盖显式结果的 `asciiTheme`、`hAnsiTheme`、`eastAsiaTheme` 和 `cstheme` 属性。
- 必要时清理命中段落和文字运行中冲突的主题字体引用，但保留非字体直接格式。
- 标题 1 至标题 4、正文、目录 1 至目录 3、题注、表格正文、脚注尾注、长引文、参考文献、答案和教学提示框分别处理，不依赖 Word 内置样式默认值。
- 同一角色包含混合中西文时，中文与西文必须分别命中已批准字体。
- 不修改公式对象内部字体；OMML、MathType/OLE、LaTeX 生成的可编辑公式对象仍按公式保护规则处理。

默认技术教材配置仍为：

- 正文：中文宋体，西文 Times New Roman。
- 章题、二级标题、三级标题：中文黑体，西文 Arial。
- 四级标题：中文宋体，西文 Times New Roman。
- 其他角色沿用当前已批准配置，调用者可明确覆盖。

### 样式与直接格式一致性

应用后必须同时验证：

- 样式定义不再通过主题字体覆盖批准字体。
- 命中对象的有效字体与批准配置一致。
- Word 打开、更新字段、重新分页并保存后，有效字体结果保持不变。
- 仅修改受控字体属性，正文文字、编号文字、公式、媒体和嵌入对象保持一致。

## 页脚字段幂等性

页码应用改为重建受控页脚，而不是向现有页脚追加字段：

1. 只有结构映射明确批准为派生页码内容的页脚才能清理和重建。
2. 每个受控奇数、偶数和首页页脚最多保留一个 `PAGE` 字段。
3. 目录与正文独立起始页码、正文连续编号及奇偶外侧位置继续遵循 V0.2.5。
4. 重复运行 `apply_profile.py` 和 `finalize_docx.py` 不得增加页脚段落或 `PAGE` 字段数量。
5. 页脚含有非页码文字、图片、章名或其他字段时不得自动清空，必须生成阻塞 QA 或只修改已验证的页码段落。
6. Word 刷新后验证实际 PDF 页码序列，不能只检查 DOCX 中的字段数量。

## Word 适配器兼容性

Microsoft Word Windows 适配器增加以下要求：

- 优先使用兼容范围更广的单参数 `Documents.Open(path)`，其余安全设置在打开前后分别应用。
- COM 布尔值和枚举使用 Word 可接受的显式类型；单个不可用的可选属性不得使整个字段刷新失败。
- 含空格的适配器路径和命令参数必须通过协议参数数组或安全编码传递，不依赖嵌套引号拼接。
- 禁用宏、外部链接更新和交互提示；只操作派生副本。
- 保存后重新打开，验证目录缓存、页码字段、有效字体和 PDF 导出。
- 只关闭适配器自行创建的 Word 实例，不终止用户已有的 Word 进程。

## 稳定指纹与终稿审计

### 页眉页脚规范化

- 稳定内容指纹按关系类型、分节引用和规范化内容比较页眉页脚，不依赖 `footer1.xml` 等物理文件名。
- Word 仅重新编号部件但内容与引用语义一致时判定为相同。
- 经结构映射批准为派生页码的页脚允许 `PAGE` 字段缓存变化；含非派生内容的页脚继续完整保护。
- 孤立且不可达的页眉页脚按 V0.2.5 规则清理或忽略，但仍被引用的部件不得忽略。

### 目录和批准替换定位

- 静态目录迁移后，审计器不再要求已删除的旧目录段落仍可定位。
- 真实 `TOC` 展开产生的目录条目按字段边界和批准标题集合验证，不使用旧静态目录段落序号。
- 已批准 `replace_identifier` 的图表编号通过替换后哈希和上下文定位验证。
- 分节边界同时支持原始文本哈希和去除批准手工编号后的规范化文本哈希。
- 审计输出必须区分内容失败、批准派生变化、字段缓存变化和定位器缺陷。

## 空白页分类

报告和审计增加：

- `intentional_recto_blank`：为保证章或正文从右页开始而产生的中间空白背页。
- `removable_trailing_blank`：尾部空段、空节或无用分页导致的空白页。
- `unexpected_blank`：无法由批准分页规则解释的空白页。

只有 `removable_trailing_blank` 可按已批准规则自动删除。`intentional_recto_blank` 应无可见页码，并在报告中说明原因；是否取消右页起排由调用者决定。

## 脚本与文档变化

- 扩展 `_common.py` 或新增独立模块，实现有效字体解析、主题字体解析和受控样式字体写入。
- 扩展 `inspect_docx.py`，盘点样式继承、主题字体和角色有效字体。
- 扩展 `apply_profile.py`，显式化受控样式字体并幂等重建页码页脚。
- 扩展 `audit_docx.py`，验证最终有效字体、目录展开、批准编号替换和空白页分类。
- 扩展 `structure_map.py`，规范化编号变化后的分节边界与审计定位器。
- 扩展 `finalize_docx.py`，在外部字段后端返回后再次验证有效字体和规范化指纹。
- 修订 Microsoft Word Windows 适配器的 COM 打开方式及命令参数传递。
- 更新 `SKILL.md`、技术教材规则、QA 报告、能力分级和适配说明。
- 配置规范若需新增字体执行策略，升级兼容版本并继续读取既有配置。

## 测试与验收

使用完全合成、不含真实书稿内容的 DOCX 验证：

1. 原主题正文为等线、标题为等线 Light，批准配置为宋体/黑体时，最终有效字体必须为宋体/黑体。
2. Heading 1 至 Heading 4、Normal、TOC 1 至 TOC 3、Caption、Quote、脚注和表格样式均覆盖中西文与复杂文字字体。
3. 字符直接格式含主题字体时，只对批准命中对象清理冲突属性。
4. 未受控样式和未命中段落保持原主题字体。
5. 缺失字体时阻塞，不回退到原主题字体。
6. 连续运行两次后，样式、页脚段落和 `PAGE` 字段数量稳定。
7. 两位数及以上奇数页页码完整显示，奇数右外侧、偶数左外侧。
8. 页脚含章名或图片时不被清空，并产生正确 QA。
9. Word 将页脚部件重新编号后，稳定指纹仍通过。
10. 真实 TOC 展开、PAGEREF 缓存刷新和批准图表编号替换不产生定位误报。
11. 正文右页起排的中间空白背页标记为 `intentional_recto_blank`，尾部空白页仍可删除。
12. Word 适配器兼容含空格路径，且不影响用户已有 Word 进程。
13. 正文指纹、表格文字、公式、OLE、媒体和嵌入对象哈希保持。
14. Word 与 LibreOffice 分别渲染；Word 为目标软件时以 Word PDF 为最终版面依据。
15. Windows、macOS、Linux、四个首批 Agent、Agent Skills 规范及全部既有测试继续通过。

1. 从最新 `main` 创建 `plan/v0.2.6-deterministic-fonts-and-audit-hardening`，新增本方案并更新索引。
2. 方案 PR 完成 QA 并获得用户明确批准后 squash merge。
3. 从新的 `main` 创建 `skill/deterministic-fonts-and-audit-hardening-v0.2.6`。
4. 实现确定性字体、页脚幂等、Word 适配器和审计修复，并增加合成测试。
5. 实现 PR 完成自动测试和 QA，获得用户明确批准后 squash merge。
6. 使用合并后的实现重新处理本地单章，确认 Word 字体栏、实际字形、目录、页码和 22 页版面。
7. 用户批准单章结果后，再对整本书执行一次性处理。
8. 后续方案变化继续创建更高版本文件，不覆盖本方案或旧方案。
