# format-monograph V0.2.3：领域感知的图表标识与人工题注

## 背景与目标

V0.2.2 将可唯一解释且获批的图表题注默认迁移为 Word `SEQ` 字段，并按章节与局部顺序解析编号。真实土木工程教材试排表明，这一默认不适用于所有专著：建筑、土木及工程图纸语境中的连字符数字可能是剖面、节点、详图或其他图纸标识，而不是题注顺序号。机械拆分、补号或重排会改变专业含义。

V0.2.3 将“保留人工可编辑图表编号”设为全局默认，并增加领域感知和逐项确认机制。当前调用者或出版社的明确要求仍具有最高优先级；只有明确要求字段编号时才允许使用 `SEQ`。

本方案只保存通用规则和合成测试。真实书稿、题名、编号清单、哈希、路径、试排文件、报告和渲染页不得提交仓库。

## 全局默认规则

1. 图号、表号及其连字符组成部分默认视为作者提供的完整人工标识，保持普通可编辑文字。
2. 默认不创建、替换或重建 `SEQ` 字段，不自动补号、改号、排序或检查连续性。
3. 图题和表题默认只应用获批的字体、字号、对齐、段距、分页及位置格式。
4. 表格合并首行中的表题默认保持原位；只有当前调用者逐项批准后才能移出表格。
5. 现有 `SEQ`、书签、`REF` 和 `PAGEREF` 保持原状。转换、重建或删除字段必须由当前调用者或出版社明确要求。
6. 疑似编号错误只报告。只有调用者确认准确替换值后，才允许修改对应标识；题名和其他文字必须保持不变。

## 建筑与土木领域解释

当资料、配置或正文语境表明内容属于建筑、土木、结构工程或工程制图时，Skill 必须分析连字符数字是否可能属于：

- 剖面或截面标识，例如 `1-1`、`2-2`。
- 节点、详图、轴线、构件或图纸索引标识。
- 章节号与专业图纸标识的混合编号。
- 出版题注编号与图纸内部编号的并列形式。

不得仅凭数字层级或连字符位置判断“缺少题注顺序号”。领域含义不明确时，保持原文并生成 QA；不得自动套用通用出版编号模式。

领域识别可使用当前调用者说明、出版社规则、任务配置、标题与题注上下文及邻近图表语义。自动识别只能生成候选和置信度，不能授权修改。

## 配置与结构映射

新建配置继续使用格式配置 schema `1.1`，在题注规则属性中增加：

- `numbering_mode`: `manual_text`（默认）或 `seq_field`。
- `preserve_identifier`: 默认 `true`。
- `domain_context`: `general`、`architecture`、`civil_engineering`、`mixed` 或 `unknown`。
- `allow_automatic_renumbering`: 默认 `false`。
- `preserve_table_cell_caption_position`: 默认 `true`。

结构映射升级为 `1.2`，读取端继续兼容 `1.0` 和 `1.1`。每个题注候选增加：

- `numbering_mode`: `manual_text` 或 `seq_field`。
- `identifier_semantics`: `publication_number`、`drawing_mark`、`mixed` 或 `unknown`。
- `domain_context` 与 `domain_confidence`。
- `action`: `preserve`、`style_only`、`replace_identifier`、`convert_to_seq` 或 `move_caption`。
- 可可靠分界时记录 `identifier_sha256` 与 `title_text_sha256`；不能可靠分界时保持 `unknown` 并阻塞文字修改。
- `replace_identifier` 必须包含调用者确认的 `replacement_identifier`，且该项单独获批。

结构映射和批准替换值只保存在任务本地，不提交仓库。候选生成器不得因为人工题注不匹配 `SEQ` 模式而标记为不完整。

## 应用与审计

- `style_only` 只修改题注格式属性，完整保留题注文字、编号和位置。
- `preserve` 不修改题注，只进入报告。
- `replace_identifier` 只能替换已确认的标识片段；应用前后必须验证题名哈希一致。
- `convert_to_seq` 只有在配置与结构映射均明确批准 `seq_field` 时才可执行。
- `move_caption` 必须独立于编号模式逐项批准；移动不得隐含字段转换。
- 内容审计增加“批准的人工标识替换清单”，验证原标识、目标标识、定位器和题名不变。任何未批准的题注文字变化均使审计失败。
- 报告区分出版题注号、专业图纸标识、混合标识和未决语义，不把未知标识描述为错误。

命令接口保持不变；`inspect_docx.py`、`validate_structure_map.py`、`apply_profile.py` 和 `audit_docx.py` 共同读取结构映射 1.2。

## 测试与验收

使用完全合成的 DOCX 覆盖：

1. 普通人工图号和表号只格式化、不创建 `SEQ`。
2. 建筑与土木语境中的 `1-1` 剖面、节点和详图标识原样保留。
3. 连字符既可作为题号组成部分，也可作为编号与题名分隔符；不得据此报告缺号。
4. 表格合并首行题注在默认模式下保持原位并可独立应用格式。
5. 领域含义不明确时生成 QA，且不修改文字。
6. 调用者确认一个错误标识后，只替换该标识，题名、正文、表格、对象和其他题注保持一致。
7. 出版社或当前调用者明确要求 `SEQ` 时，既有字段流程仍可使用并通过内容审计。
8. 结构映射 1.0/1.1 继续可读；只有 1.2 可授权人工标识替换和领域语义。
9. Windows、macOS、Linux、LibreOffice 渲染、Agent Skills 规范及现有全部回归测试继续通过。

真实书稿仍只在用户本地运行。完成结构与内容审计后，干净稿和审阅稿必须逐页渲染检查。

3. 从新的 `main` 创建 `skill/domain-aware-captions-v0.2.3`，实现配置属性、结构映射 1.2、领域候选、格式应用和内容审计。
4. 使用合成 DOCX 完成跨平台与字段兼容测试，不提交真实书稿资料。
5. 实现 PR 经 QA 和用户明确批准后合并。
6. 使用合并后的 V0.2.3 在本地重新生成单章结构映射，执行已确认的人工编号修正，并完成逐页视觉 QA。
7. 单章通过后再进入整书一次性试排。

任何后续方案变化必须新增更高版本方案文件，不得覆盖本文件。
