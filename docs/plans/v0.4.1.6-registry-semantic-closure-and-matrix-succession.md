## 4. Route Closure And Current Closure

`route_matrix_version` selects only the historical artifact route. It never
means latest, highest, directory-derived, read-compatible, or automatic
upgrade. `CURRENT_SCHEMA_CLOSURE_MATRIX_VERSION` is a stage-owned explicit
pointer:

1. P3a-R changes it from 1.1 to 1.2 only when its complete atomic unit passes.
2. P3b-B changes it from 1.2 to 1.3 only when the complete formal successor
   chain and matrix 1.3 pass atomically.
3. After a switch, the preceding matrix remains responsible only for immutable
   historical snapshot closure, never for future physical-directory equality.

Matrix 1.3 inherits every 1.2 route/resource and adds the complete formal chain
plus `artifact-contract-matrix.v1.3.schema.json` as `contract_metadata`.
P3b-B rollback without downstream consumers deletes the 1.3 chain and restores
current closure 1.2. P3b-O does not change the pointer. A later deficit is 1.4
or higher.

The later implementation task must enumerate every matrix, route, schema,
offline-registry, routed-contract, and artifact-validator entry point in
`profile_v2_artifacts.py`, including the production call graph. Every
production-reachable artifact chain must validate current closure before its
first target artifact route/schema/registry/authority load. Raw historical or
component inspection may skip current closure only if it is explicitly read-only,
cannot issue artifact validity or runtime state, and is unreachable from the
production graph. `profile_v2_registry` must not reverse-depend on artifacts.

Current-closure bootstrap may read only the explicitly selected closure matrix,
its validating Schema, and declared Schema documents. It cannot route or
validate a target artifact. No public API, cache framework, or state machine is
required; an unclosable need inside the whitelist is `CONTRACT_GAP`/`STOP`.

## 5. Registry Semantic Closure

Registry 2.3 defines reusable atomic property semantics only: semantic-object
kinds; data type; unit/dimension; precision, enum, and range; cross-property
constraint references; modes/layers; QA and missing strategies; and
executor/auditor capability availability. V0.4.0 default values remain in later
P3b-B/O `monograph-base` rule assets. The registry must represent those values
without copying them as registry defaults.

Decision-to-property mapping is many-to-many. Process, approval, and protection
requirements may be `non_registry_contract`, but each must name an owner and
exact source. Opaque decision-derived properties are forbidden. Neither a
171/150/20/1 count nor a generic property proves semantic closure. The 21
future-primary decisions require individual classification; they cannot all be
bound to content protection or gain V0.4.2/V0.4.3 appearance defaults early.

Constraints have no artificial count target: every recognized obligation is
either expressed by the registry or explicitly assigned to a later rule/executor
contract. The implemented executor and auditor sets remain empty. Strict
validation rejects `reserved`/`unavailable`; `declaration_intent` explicitly
accepts `reserved`. `full_production` requires both machine closure and
line-by-line semantic acceptance.
