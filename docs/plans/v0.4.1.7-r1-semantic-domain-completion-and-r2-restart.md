Status: docs-only planning candidate. This document changes neither production
data nor an implementation authorization. Its merge would adopt a new planning

P3b, a CLI, release, Ready, or merge.

## 1. Purpose, Finding, Authority, And Non-Downgrade Rule

V0.4.1.6 correctly assigned registry 2.3 and matrix 1.2 to P3a-R, but its
local R1 taxonomy/projection input form is now diagnosed as R1_INPUT_GAP /
CONTRACT_GAP: it names only partly closed domains and cannot unambiguously
generate complete enum members, object shapes, ranges, precisions, units, or
cross-field invariants. A count, a category label, a free-text requirement, or
a reserved future capability is not a closed semantic-domain contract.

This finding does not lower any requirement. It requires an independently
reviewable, test-only semantic-domain contract before a new R2 restart can
create the planned registry 2.3 or matrix 1.2 artifacts. V0.4.0 remains the
only authority for all 171 format decisions, their exact semantic values, and
their source anchors. Later plans may govern lifecycle, owners, routes,
versions, proof timing, and boundaries; they cannot replace, infer, or alter a
V0.4.0 format value.

C2 synthetic performance remains STOP. PR #43 remains Draft historical
evidence. Default-closed behavior, non-delivery, no public CLI, historical
compatibility, fail-closed validation, privacy, determinism, and all Word,
visual, and long-document gates remain unchanged. Nothing here claims an
implemented registry, matrix, monograph base, DOCX behavior, whole-book
validation, long-document reliability, or completed P3.

## 6. Canonical Machine-Contract Requirements

The extractor and machine contract compare in both directions. The extractor
mechanically establishes exactly 171 frozen decision rows and their original
text; it does not infer atomic semantics or an atomic-obligation total. Each
decision row may split into one or more atomic obligations. Bidirectional gates
separately prove that every decision row is disposed and that every atomic
obligation has exact source references. Line-by-line human review confirms that
each split is complete. No gate may hard-code the atomic-obligation count as
171, and no contract-side enumeration may become the decision-row oracle.

| Contract kind | Required structured content |
| --- | --- |
| property | representation_kind, domain_scope, value schema/object shape, cross-field invariants, unit/dimension/allowed units, comparison precision, ranges, mode/layer, QA/missing behavior, capability references, and exact source references. |
| constraint | Dependency classes, registry-property IDs, external obligations, capability dependencies, decidable invariants, validator owner, and source references. |
| capability | Executor or auditor class, availability, owner, and source. It must not invent implemented. |
| later_rule / non_registry_contract | Exact owner, target stage, contract locator, input/output boundary, original unresolved obligation, and source reference. |

Every identifier is stable, typed, and cross-referenced. The contract must
prove that every source decision row is fully disposed, including all of its
atomic splits, and that every atomic obligation has exact source references and
exactly one preserved disposition or explicit split with no lost semantic
field. A prose semantic_requirements field, a generic opaque string property, a
count-only closure, or an untyped reserved/future entry is insufficient.

Not-applicable is not a top-level contract kind. It may appear only as a
structured applicability field on an already classified property, constraint,
capability, later_rule, or non_registry_contract entity. That field must carry
a fixed reason_code, authority-backed source, and explanation. It cannot
dispose an entire source obligation, replace a top-level class, mask an
unresolved obligation, or contribute to unresolved-zero closure.

## 7. Domain Scope, Preservation, And Unresolved Closure

Each property or constraint declares one of these scopes:

| domain_scope | Required closure |
| --- | --- |
| project_closed | Every member is individually enumerated from frozen project sources. |
| source_preserved | Names frozen source system/version/type, canonical preservation shape and allowed fields, unit/finite constraints, round-trip equivalence, provenance, and validator boundary. It assigns no execution semantics. |
| external_versioned | Binds owner, external version, locator, digest, project mapping, and offline validator boundary. |
| project_open_constrained | States exact shape, finite/range rules, and cross-field invariants. |

Closed enums list every member. A single project sample, Word/OOXML support
range, or domain knowledge cannot enlarge a closed domain. An unresolved
obligation cannot receive an automatic value or opaque fallback. Reclassification
to later_rule or non_registry_contract must prove that the obligation is
intrinsically outside the registry and preserve its original obligation, owner,
target stage, locator, input/output boundary, and source. reserved, future, or
free text is not closure. Before acceptance, unresolved obligations must be
zero.

page.paper-size is deliberately a comparison task, not a pre-decided enum: R1
must evaluate whether its source supports project_closed, source_preserved, or
positive finite width/height open geometry. Orientation is independent. A source
code may be retained only as non-authoritative metadata, and the contract must
state unit, custom-paper, and cross-field boundaries. The plan decides neither
that result nor the result for table.alignment or any other domain.

## 8. R1 Sequence And Acceptance Binding

R1 follows this strict order:

1. exact-main and staleness entry;
2. frozen-blob extractor;
3. test-first red contract;
4. complete machine contract;
5. deterministic human-readable report;
6. focused, mutation, bidirectional, and report-byte tests;
7. manager review;
8. independent review;
9. explicit user acceptance of the exact checkpoint.

Acceptance binds the R1 commit and tree; the exact path + git_blob_oid + raw
SHA-256 for all three assets; canonical JSON digest; generated-report digest;
all authority/lifecycle path + git_blob_oid identities; and manager,
independent-review, and user acceptance coordinates. A normal continue message
is not acceptance. The binding is recorded in session evidence or a later entry
package, never by writing review coordinates into R1 files and changing their
bytes. Any bound-byte, digest, authority-blob, review-coordinate, or
user-acceptance change invalidates acceptance.

Canonical JSON serialization, raw SHA-256, canonical digest, report ordering,
UTF-8 encoding, LF line endings, and byte equality are frozen by the tests.
The report cannot be hand-edited or accepted independently of the JSON
contract.

## 9. R2 Restart And Preserved Implementation Boundaries

Only after a valid new R1 acceptance may the user separately authorize an R2
restart. R2 then begins test-first with an explicit red contract and uses the
planned, still-unreleased registry 2.3 and matrix 1.2 identities under the
unchanged V0.4.1.6 ownership and fail-closed boundaries. Old R1 acceptance,
diagnostic checkpoint, and byte binding are invalid inputs.

For a single typed binding, the generated catalog and public validator must
both accept valid input and both reject invalid input. Mutation coverage must
include flat and type-correct but semantically illegal input, with its oracle
derived from accepted R1 plus an independent mutation corpus. A generated
catalog cannot be used as the validator's sole oracle.

Focused and independent narrow semantic probes run before long regression.
The historic 247 tests are historical evidence only. A new stage freezes an
actual current-tree non-C2 manifest, excludes only the two separately frozen C2
modules, and records its actual collection/run count instead of permanently
hard-coding 247. C2 remains STOP.

This plan changes none of V0.4.1.6's registry 2.3/matrix 1.2 ownership,
matrix/current-closure rule, historical 1.1/2.2 compatibility, fail-closed
requirements, whitelist principle, P3b ordering, or rollback limits. It adds
no public API, cache, approval Schema, state machine, second registry, or
version inflation.

## 10. Tests, Rollback, Authorization, And Non-Claims

The R1 test suite must cover authority-object identity, exact 171-row
extraction, source-reference closure, structured-field completeness, closed and
open domain rules, unresolved-zero closure, duplicate/extra/missing entries,
mutation rejection, contract/report digest and byte equality, and privacy.

human semantic-review obligation; tests do not self-accept a semantic mapping.

or any diagnostic checkpoint. Re-entering R2 always requires a valid new R1
acceptance and separate user authorization. The V0.4.1.6 deletion or
coordinated-successor rollback rules continue to govern planned registry/matrix
assets once they exist.
