# 专著格式化工作流：统一开发方案

版本：确认版 1；确认日期：2026-09-11。

状态：用户已明确同意完整方案并授权上传 GitHub。此版本承接草案 3；方案确认和上传不等于业务代码完成、测试通过、合并或发布授权。合入 main 后，本文件成为仓库唯一持续维护的开发方案。

## 1. 方案地位与使用方式

本方案将本次确认的需求、内容保护边界、代码评估结论、开发顺序和验收条件收敛为一个开发入口。用户已整体确认；后续任务、实现、评审和验收以本方案为准。仓库入口随本方案 PR 合入 main 生效，合入前不将分支状态误报为稳定分支状态。

依据顺序为：

1. 用户在本次交流及后续明确确认的要求。
2. 本方案经确认的当前版本。
3. 本方案要求的配置与实现，仅用于执行本方案，不构成新增需求来源。
4. V0.4.0 及其他历史方案、测试、实现和评估记录，只提供参考或证据，不再作为运行或开发时补充要求的入口。

本次需求高于 V0.4.0。适用格式和流程已经改写到本方案正文，旧方案中的“冻结”“不可覆盖”“必须”不再有独立约束力。旧文档变动不会自动改变本方案；本方案未写入的旧要求不生效，不得再用“按旧方案执行”引入新门槛。

此前的需求整理文档用于追溯用户确认，现状评估报告用于追溯检查依据；两者不再分别维护新的实施指令。开发人员不需要拼接多份历史修订才能知道该做什么。本版中具体格式取舍和技术建议已随完整方案获得确认；技术选择仍可按第 10 节在相同目标和边界内据实优化，不代表已有实现证据。

## 2. 产品目标、范围与非目标

### 2.1 产品目标

用户提交整本专著，由 agent 分批理解稿件并提出大纲，与用户交流确认后组织格式化；明确事项大部分自动完成，冲突和疑问有合理、高效的人工处理方式，最终交付 DOCX。

用户明确的核心交付标准为：稿件按指定格式完成格式化；不改变不应修改的稿件内容；图表按照原有前后文位置放置。图表位置属于内容及结构保护要求，优先于为了外观统一而移动对象的默认策略。

MVP 是“能够完成目标用户核心任务的最小可用产品”。功能及流程完整，实现保持简单；不能以只处理短篇或简单文档的演示代替目标产品，也不为所有罕见异常持续开发自动修复功能。

### 2.2 必须支持的范围

- DOC、DOCX 输入，允许统一输出 DOCX；输入一般为整本稿件。
- 目标处理 1000 页、包含大量且多种形式的图片、表格和公式的复杂稿件。
- 首先由 Codex 使用；核心处理能力与 agent 平台差异分开，之后可扩展其他 agent。
- Windows、macOS 均在目标范围。本机 macOS 先开发和实测；Windows 适配先实现，后续实机试运行，未实测不得声称通过。
- Microsoft Word 是排版验收依据；WPS 验证基本打开、编辑和对象可用性，显示差异以 Word 为准。
- 单任务受控工作副本、真实批次进度、暂停恢复、人工决定保存，以及全书内容、格式、字段和版面检查。

### 2.3 首版不承担的工作

正文润色和校对、数据或公式改写、参考文献内容规范化、自动创作缺失章节；任意文档和任意异常的全自动修复；完整所见即所得编辑器；多 agent 同时写一份稿件；实时多人编辑；跨机器处理中同步；全部其他 agent 的接入；所有历史 Word/WPS 版本的逐像素一致。

这些非目标不削减核心格式范围。普通任务所需功能尚未实现时，不得用“人工判断”或“保持原样”代替完成。

## 3. 内容保护与已授权操作

### 3.1 允许的操作

| 类别 | 允许范围 | 必须保持 |
| --- | --- | --- |
| 格式属性 | 符合本次规则的字体、字号、段距、缩进、边框、分页及有依据的布局调整 | 作者内容、语义顺序和对象归属 |
| 目录与编号 | 根据已确认大纲和规则生成或更新目录、章节编号、图表编号、页码及获批字段结果 | 标题正文、题注正文、实际引用对象 |
| 纯排版空白 | 将确定仅用于缩进或间距的空格、空段替换成真正的段落格式 | 正文字符；代码、公式、引文等有语义或用途不明的空白 |
| 手写引用编号 | 图表重编号后，同步正文中唯一确定指向同一图表的编号部分 | 句子其余文字及引用目标 |

后两项已经用户明确授权，确定属于范围内时自动处理，不对每个对象重复索要同类授权。不确定用途或引用关系时才提出具体问题。

### 3.2 禁止的操作

不得润色、纠错、补写或删除授权范围外的文字、标点、数据、参考文献内容；不得改变公式含义、引用目标、图表与题注的对应；不得将原本可编辑公式栅格化。不得自动接受或拒绝修订、删除批注，或因无法理解而删除嵌入对象。

排版空白整理不授权合并含正文的段落、任意删除硬换行或全局去空格。引用同步不授权全局替换数字或改写整句话。原稿及与当前操作无关的用户文档不覆盖。

### 3.3 执行和检查要求

每项改变字符或结构的操作记录对象、准确范围、前后变化、来源规则或决定，以及需要保持的关联。利用已有记录机制或简单数据结构即可，不建立通用语义证明平台。

核验同时覆盖作者内容、复杂对象及关联、允许变化的正确性。不能只比较全文纯文本、对象数量或整个 DOCX 字节；也不能全局忽略空白、数字、字段结果或整个段落来消除差异。转换 DOC 形成 DOCX 的步骤同样受内容保护约束。

核验分为受保护文字、媒体/嵌入载荷、结构与引用关联、限定允许变化四部分。纯格式 XML、运行片段划分或 Word 序列化发生变化时，按明确属性和可还原的内容顺序比较，不要求整个包字节不变；未知差异不能一概归为格式噪声。允许变化必须核对实际前后值及目标，不以“有操作日志”代替正确性检查。

DOC 输入保留两段核验：原 DOC 到转换 DOCX 的内容及对象核验，转换 DOCX 到最终稿的修改核验。不能只以转换后的文件作为基准而漏掉转换损失。若某类旧对象转换后无法可靠比较或显示，记录具体范围并处理，不声称已证明无损。

图号与相关引用作为关联工作处理。无法可靠保持对应时，暂停这组变更，保留此前一致结果。工具新引入的损坏不得作为“用户接受的格式例外”放行。

### 3.4 图表与前后文位置保护

图表须保留在原有前后文之间，保持所属章节和语义上下文、相对于作者文字和其他对象的阅读顺序，以及图表与题注、注释的对应关系。具有内容组织意义的段落和容器归属同样保护。不能为了居中、同页、填满页面或靠近某次引用，自动跨越正文段落、集中到章末或移到其他上下文。

排版引起的自然分页按本任务页面规则处理；验收定位以原有上下文关系为依据，不以旧页码作为对象身份。浮动图片和表格同时检查锚点、环绕及目标 Word 中的实际显示，不能只因锚点未变就认定位置保护通过。

保护目标不是固定旧物理坐标或每个内部 XML 包装。内部布局表达确需调整时，仍须同时满足已授权格式、原有上下文顺序、载荷和关联保护；该说明不授权拆合含文字段落、移动有意义锚点或更换有意义容器。不能因为内部表示不同误报位置损坏，也不能因为内部表示相同漏报视觉移位。

记录图表及前后文的稳定定位关系，修改后核对文字—对象顺序、题注关联及必要的页面显示；原稿本身含浮动布局、图文混排或多个候选关联而无法确定时，先保留并展示上下文。格式要求（包括图题在下、表题在上、图题同页等）若需要改变原有上下文位置，必须提出具体冲突及建议，由用户决定，不能静默移动。不得以修改记录中的定位关系来掩盖实际移位。

## 4. 本方案直接规定的格式要求

本节已将适用的旧格式重新整理为当前要求，执行、实现和验收直接读取本节，**不再通过“参照 V0.4.0”补充规则**。以下是默认模板的明确要求；任务指定格式按 4.1 覆盖。保持策略也是确定的处理要求，不等于功能缺失。

### 4.1 规则来源、适用范围与通用约定

1. 当前任务明确要求和已保存的人工决定优先，其次为本次指定且适用于相应对象的出版社要求或模板，最后由本节默认格式补足。同层冲突、适用范围不明且影响处理时提问，不按加载顺序或最后写入决议。任何格式来源均不能自行扩大第 3 节的内容修改权限。
2. 自然语言要求、模板或样稿可以由 agent 提取候选规则。证据清楚的规则按已确认任务范围执行；截图、OCR 和不确定推断不能静默成为确定要求。用户无需编辑 JSON；不开发任意模板全自动解释器。
3. 执行前形成一份本任务的最终规则。每个实际使用的属性记录对象范围、值或保持策略、来源、覆盖关系和必要的决定；不要求实现六层 Profile、独立模块注册系统或完整历史规则迁移。
4. 本节“确认”指当前任务已有有效依据或保存的用户决定，不要求逐对象重复点击。对象身份明确且条件满足时自动处理；只有真实歧义、冲突或超出授权的改变才交人工。领域规则按相关对象生效，不能扩散到全书普通文本；不要求用户选择内部模块名。
5. 字号和段距单位为 pt；“最小行距”允许高字符、图片及公式撑高，不能实现为固定行距。“字符缩进”用段落/列表属性表达，不插入空格或制表符。“同页”通过合理分页属性和目标 Word 检查实现，不改变文字顺序或以不可读缩小强行满足。
6. 表中未指定的格式属性，优先继承本节明确指出的对应角色；未指定继承时保持原稿有效值，不由开发人员另外选一个外观默认值。字体缺失时报告具体字体和受影响范围，采用用户已有替代要求或集中确认替代，不以系统静默回退宣称符合原字体要求。
7. 不新增用于排版的真实空段、空格或制表符。原稿明确的纯排版空格、空段按第 3 节整理；原有制表符不因这项授权自动删除，有语义及用途不明的空白保持并按需判断。新增目录等获批派生内容也使用真实格式属性。
8. 角色识别不以文字关键词、长度或外观单独决定。标题、正文、代码、引文、注释、题注、布局表等应分别处理；全局样式修改不能覆盖有语义的字符格式、对象内部载荷和引用关系。

### 4.2 页面与分节

- 每节纸张大小、方向、页边距、装订线、页眉页脚距离及分栏默认保持。不自动改成单栏或双栏，不采用比例页边距或固定距离作为隐含默认。
- 不因标题级别强制章前新页，也不批量取消原有分页。已确认的新普通分节继承当前位置有效分栏；横向节结束后恢复此前布局，页码连续。
- 宽图或宽表需要横向页时，先呈现具体布局建议；已有任务要求足以覆盖该对象时直接执行，否则确认后建立所需分节。不能仅因尺寸大就自动横向。横向页的页眉页脚和页码按正常阅读方向检查。
- 空白页按成因处理，不提供无依据的“删除页面”。确定的排版空段可以按已授权范围整理；人工分页、奇偶页布局、对象占位、表格尾段及分节产生的空白不得一概删除。冗余分节只有在来源及影响明确、布局与页码关系可验证时受控清理，否则保持并提出具体问题。

### 4.3 书名页及前置部分

- 不设计或补写封面，只格式化已有且识别明确的内容。书名：中文黑体、西文 Times New Roman，22pt、加粗、居中、最小行距 33pt。
- 副标题：黑体/Times New Roman、16pt、常规字重、居中。作者：宋体/Times New Roman、14pt、常规字重、居中。机构、出版社、日期：宋体/Times New Roman、10.5pt。
- 纯文字书名块可垂直居中；复杂书名页保持对象相对布局和顺序。书名页不显示页码。
- 版权页、题献、题词保持原布局并进入视觉复核；前置内容顺序保持。前置标题默认不编号，目录收录由最终大纲决定。
- 书名、版权、题献和题词页默认组成前置不编号区，不显示页码，也不消耗后续前置逻辑页码。具体边界以对象角色及本任务确认结果为准，不能仅按物理页序猜测。

### 4.4 正式目录

- 新建目录题名默认“目录”。已有自定义题名不改写；明确仅为视觉间距的字间空格可按第 3 节整理。题名：黑体/Times New Roman、18pt、加粗、居中，段前 0、段后 18pt，与下一段同页。
- 默认收录章、二级、三级标题，四级按最终大纲决定；前置和后置标题同样按批准的收录关系处理。不同位置的同名标题是不同对象，不因文字相同误删。
- 目录项中文宋体、西文 Times New Roman。章项 10.5pt、加粗、段前 6pt、段后 0；二级 10.5pt、常规、段前后 0；三四级 9pt、常规、段前后 0。层级缩进分别 0/2/4/6 字符，点引导线、页码右对齐；行距未另定时保持已有有效值，新建项继承正文最小 18pt。
- 使用真实、可更新的 Word 动态 TOC，来源只限批准标题。可使用标题样式来源；标题混有会污染目录的复杂对象时采用独立、纯文本的目录来源，文本必须与批准标题一致。一份正式目录选择一种一致的来源策略，不重复计入两种来源。
- 目录结果不得含图片、DrawingML/VML、OLE、文本框、表格、空项、同一来源的重复项或未批准标题。不为清理目录而删改标题里的作者对象。
- 各批次只更新目录源清单和状态；全书对象处理结束后统一创建、更新正式 TOC。Word 更新后仍须保持上述样式，首次结果不是最终页码证据。

### 4.5 页码与页眉页脚

- 首个确认需要编号的前置页从阿拉伯数字 1 开始，后续前置和目录连续；目录前无编号前置内容时，目录首页从 1 开始。已有正确且符合本任务的边界保持。
- 正文独立从阿拉伯数字 1 开始，后续章节、横向节和附录连续，不逐章重启。
- 默认页脚外侧页码：奇数页右、偶数页左，宋体/Times New Roman、9pt、裸阿拉伯数字。章首页隐藏运行页眉但显示页码；有意空白页计入相应序列但不显示运行页眉和页码。
- 复杂页眉页脚默认保留。若与本次页码要求冲突，明确提出受影响部分的处理方案，不能为实现简单页码而重建整个页眉页脚、删除其他内容。未提供运行页眉文字时不自行创作。
- 页面阶段明确不编号区、首个编号前置页、正文重启点、奇偶页及章首页规则。最终化只能在该配置下更新获批字段，不新增、删除或重建分节，不改编号边界、起始值、格式及页眉页脚规则。

### 4.6 标题与标题编号

标题中文黑体，西文和数字 Times New Roman，编号与标题使用一致字号和字重：

| 层级 | 字号与字重 | 对齐 | 最小行距 | 段前 / 段后 |
| --- | --- | --- | --- | --- |
| 章 | 18pt、加粗 | 居中 | 27pt | 24 / 18pt |
| 二级 | 14pt、加粗 | 左对齐 | 21pt | 18 / 9pt |
| 三级 | 12pt、加粗 | 左对齐 | 18pt | 12 / 6pt |
| 四级 | 10.5pt、加粗 | 左对齐 | 18pt | 9 / 3pt |

- 首行、左、右和悬挂缩进均为 0，清理冲突的列表缩进属性；标题段内不拆页，并与随后内容同页。超长或含复杂对象而无法满足时定位处理，不能截断内容。
- 依最终大纲建立 Word 关联多级编号，只移除已确定属于旧编号的前缀，标题正文不变。任务无其他编号方案时采用“第1章、1.1、1.1.1、1.1.1.1”。前缀有歧义时先判断。
- 前置、参考文献、习题、附录等标题按实际层级和编号角色处理，不一律套章题，不强制新页。附录编号与正文序列隔离。

### 4.7 普通正文与中文排版边界

- 宋体/Times New Roman、10.5pt、常规字重，两端对齐且末行自然左齐；不用分散对齐。最小行距 18pt，首行缩进 2 字符，左右缩进及段前后均为 0。
- 开启孤行控制；普通正文不设置与下一段同页或整段不拆页。科学符号、语义强调、超链接、修订、批注及复杂对象按各自保护规则处理，不能被普通正文常规字重一概覆盖。
- 中文标点的行首行尾问题可用不改变字符的排版设置调整，并以 Word 版面检查为依据。标点字符、全半角、引号、书名号、省略号、破折号、连字符、减号、乘号与字母 x 不自动转换。
- 内容性标点疑问可在发现时报告；不把全面标点校对建设成 MVP 必备子系统。公式、URL/email/DOI、路径、代码、型号、直接引文、参考文献及字段代码均不得进行批量字符清理。

### 4.8 科学符号

- 仅对有充分语义依据、且可在不改字符与公式含义的范围内修改的符号应用领域字形：变量、变量下标、任意函数、参数、几何点/线段/弧、标量物理量用斜体；已定义函数/算子、作为常量的 e/i/π、微分 d、变分算子、单位、说明性下标、化学符号、型号代码及普通数字用正体。
- 向量变量采用粗斜体。矩阵、张量及同字符不同含义的情况按语义确定，缺少依据时保持并集中提问；不得仅凭字母、正则或周围是否加粗判断。
- 对实际需要处理的符号记录必要的“符号—语义—作用范围—决定”，不要求无科学符号任务生成空符号表，也不另外建设全书科学内容解释平台。
- 原有公式内部结构和数学字体默认保持，不全局改成 Times New Roman；优先处理能够可靠定位的外部符号文本。科学符号语义字形优先于关键词或标签加粗，避免把标量误变成向量。不能可靠修改的特殊载体保留并定位疑问，不宣称已经统一。

### 4.9 列表与列举

- 列表与表格、普通编号段落分别识别。文字字体、字号及最小行距继承正文，悬挂缩进，续行与条目文字对齐，每深入一层增加 2 字符。
- 保留现有列表编号和项目符号。只有任务明确要求重建时才生成彼此独立的 Word 列表；无指定编号方案时后备为一级“（1）”、二级“1）”、三级“a）”。不新增装饰性或图片项目符号。
- 列表不作为标题或目录来源，不插空段。行内列举保持同一段，不为统一列表外观拆开正文；歧义编号段落交人工判断。列表编号权限不能由图表引用同步授权推导。

### 4.10 引文与注释

- 短引文和仍处于正文语流的长引文继承正文；长度不触发缩小字号或增加左右缩进。已有或明确识别的块引文可保留独立布局，无任务要求时字体、字号、行距同正文，原有块布局的其他属性保持。引文文字和标点不变。
- 脚注、尾注、普通“注：”、图注、表注及参考文献分别处理。已有真实 Word 脚注/尾注保持类型、位置、编号范围及关联，不转换为正文模拟注释。手写模拟注释不自动转换类型，确需转换单独确认其范围。
- 脚注和尾注文字：宋体/Times New Roman、9pt、两端对齐、最小行距 15pt、段前后 0、标记悬挂对齐、孤行控制。长注释允许跨页，不强制整条不拆页；不移动注标相对于标点的位置。
- 注释分隔线保持；确需修复时只处理明确范围。普通段落“注：”无其他要求时继承正文，不误套脚注、图注或表注样式。

### 4.11 公式

- 保持 OMML、MathType/OLE、EQ 等原有公式载体，不自动互转；原本可编辑的公式保持可编辑，禁止栅格化。
- **原稿已有的公式图片保留并标记“原稿为图片、不可编辑”，不 OCR 重建，也不单凭其存在阻断全书。** 仍须检查可读性、显示和对应关系；受裁切或无法保持的对象进入问题处理。该条是本方案对旧“公式图片一律阻断”的明确调整。
- 正文行内公式所在行最小 18pt并允许随高度扩展；其他角色中的行内公式继承所在角色的弹性行距。独立公式居中，段前后 6pt，最小 18pt 或自动行距，不裁切矩阵和高公式。
- 原稿无编号时不凭空加号。已有公式编号默认保持；任务要求调整时在标题编号完成后处理，明确序列、关联和允许变化范围；不将图表手写引用的同步授权扩大为任意公式文字修改。
- 多行公式保持分组、矩阵与运算关系。可在载体支持且无需增删字符时，按确认布局在运算符后视觉换行、关系符对齐；不重复运算符。需要改公式载荷或语义不确定时保持并提出具体问题。
- 溢出不得通过擅改单栏、横向或不可读缩小绕过；提供有依据的布局选项。

### 4.12 图片、图题和图注

- 本节所有位置、尺寸和分页操作均受 3.4 约束；“居中”“嵌入型”“图题同页”不授权改变图表的原有前后文位置。
- 保持媒体原始字节，不重采样、不重新压缩、不改裁剪；保护有意义的位置、锚点、环绕、层叠、组合、顺序和引用关系。确需位置或尺寸调整时在当前格式要求的范围内执行，影响含义或布局归属时先判断。
- 无指定要求且没有有意义原布局时，采用嵌入型、居中，按比例限制在当前栏或版心内，不自动放大。独立图片段缩进 0、单倍/自动行距、段前 6pt、段后 0，与图题绑定；图文混合段不直接套独立图片样式或拆段。
- 图题在图下：宋体/Times New Roman、9pt、居中、最小行距 15pt、段前 0。图片与图题应同页；无法在可读尺寸下满足时交人工决定布局，不擅自压缩。
- 图注在图题下：宋体/Times New Roman、9pt、左对齐、最小 15pt、段前 3pt。保持“注”“注1”“资料来源”等已有标签及文字，不自动补写；短图注尽量与图题同页。
- 图题或最后一条图注后接正文/列表时段后 18pt；接标题、图片、表格、独立公式或显式分页时不额外增加该间距（段后 0），不插空段。
- 装饰图片不编号。图号和明确指向它的手写引用按 4.22 处理；工程剖面、节点和详图内部标识不当作普通图号批量替换。

### 4.13 表格、表题和表注

表格及关联题注、表注保持原有上下文位置，遵守 3.4；调整边框、宽度、行跨页和表头重复不能改变与作者段落的顺序。

先确定表格语义和表头范围，再应用边框，不因含图片/公式就判为布局容器，也不默认首行都是表头。

| 表格类型 | 默认边框及主要处理 |
| --- | --- |
| 简单数据表 | 三线表，顶底线 1pt、表头分隔线 0.5pt、无竖线 |
| 多级表头表 | 表头居中，保留必要层级线，外框 1pt、内部必要线 0.5pt |
| 工程参数表 | 细网格，外框和分组线 1pt、内部线 0.5pt |
| 文字对照表 | 已确认需要外框时外框 1pt、内部线 0.5pt，长文字左对齐；未确定外框需求时保持原框线拓扑 |
| 含图片/公式的数据表 | 使用所属语义表类型的边框，内容居中，保护载体 |
| 图片/公式布局容器表 | 无边框、不重复表头、不生成表号 |
| 无边框排列表 | 保持无边框，按内容与行列关系处理 |
| 页面布局表或有意浮动表 | 保持整体布局和锚点，不自动套普通数据表预设 |

- 普通语义表整表居中、无环绕，保护位置和顺序。单元格默认水平、垂直居中；长文字默认左对齐，任务要求时可两端对齐；DOI/代码左对齐，小数列按小数点对齐。列语义不明先判断。
- 表题在表上：宋体/Times New Roman、9pt、居中、最小 15pt、段前 6pt、段后 3pt，与表头或首数据行同页。题注正文不改。
- 单元格文字：宋体/Times New Roman、9pt、最小 15pt、段前后 0、首行缩进 0；单元格边距上下 1mm、左右 1.5mm。公式、代码及其他有语义的字符例外继续受保护。
- 保持列宽比例和自然宽度，不强制拉到 100% 版心；溢出按具体布局处理。只重复已确认的完整语义表头，普通行不跨页拆分，超高行允许拆分并报告，不为“整行同页”截断内容。
- 表注在表下：宋体/Times New Roman、9pt、左对齐、最小 15pt、段前 3pt。最后一条表注的段后间距采用 4.12 的后续对象规则；没有表注时也不插空段模拟间隔。
- 保留无号表的无号状态，任务要求新增编号时才生成；已有表号及手写引用按 4.22 执行。续表仅处理已有或明确批准的断点，不自动补写续表题注文字。

### 4.14 定义、定理、证明、例题

- 定义、定理、证明默认行内展示，无边框、无底纹。标签及编号宋体/Times New Roman、10.5pt、加粗；内容同字体字号、常规字重。
- 首行缩进 2 字符、段前 6pt、段后 0、最小行距继承正文，标签与第一段内容同页；后续段落继承正文。不为统一标签与正文布局合并原有含文字段落。
- 独立编号序列及证明结束标记保持；不补写证明标记。确需变更序列时单独明确本任务的编号规则及范围，在标题编号后执行。
- “例”“例题”“算例”“解”“解析”等已识别标签宋体/Times New Roman、10.5pt、加粗；内容继承正文，行内、无装饰，首段段前 6pt，标签与首行同页。保留例题独立编号，不自动生成或重建，不生成、求解或修改答案。

### 4.15 习题、答案与提示

- 稿件含明确习题/答案对象时应用相应格式，无需建设独立教材模块才能处理。“习题”等标题按大纲实际级别，不固定章级。
- 题目正文宋体/Times New Roman、10.5pt、最小 18pt、首行缩进 0；编号加粗、悬挂对齐，保持独立编号及选项布局。答案留在原位置，标签宋体/Times New Roman 加粗，内容继承正文；不生成、核对、改写答案。
- 普通提示/注意：标签宋体/Times New Roman、10.5pt、加粗，内容常规字重、行距继承正文，段前后 6pt，默认无装饰。保持已有容器，不强制转换为单单元格表格，不默认楷体。
- 明确要求新框体且范围确定时，采用黑色 0.5pt 边框、无颜色底纹、内边距 2mm、正文基础字体、无图标。不能把长提示放入不可跨页而会截断内容的文本框。

### 4.16 代码与算法

- 代码字符、空格、制表符、换行逐字符保护，排版空白整理不进入代码载荷。
- 明确的行内代码用 Consolas，中文回退宋体，10.5pt。代码块 Consolas/宋体、9pt、左对齐、最小 15pt、首行缩进 0、左缩进 2 字符、段前后 6pt；不自动断字、不两端对齐，默认无语法高亮和边框。
- 长行仅做视觉折行，不插入真实换行；折行会引发显示歧义时交人工判断。既有有意义的代码颜色及字符强调不在“默认无高亮”名义下清除。
- 算法自然语言继承正文，伪代码采用代码格式；标签宋体/Times New Roman、10.5pt、加粗；原编号保持，不自动编号。

### 4.17 参考文献

- 标题按实际层级，通常不编号，是否入目录由大纲决定；不与脚注/尾注合并建模。
- 条目宋体/Times New Roman、9pt、左对齐、最小 15pt、段前后 0、悬挂缩进、孤行控制。编号条目续行与条目文字起点对齐；非编号条目保持已有悬挂量，没有明确值时采用正文的 2 字符作为当前后备值。
- 保持条目顺序、编号、引用样式、标点和内容；不重排、不规范化、不查询 DOI，不将任何参考文献标准自动转为内容编辑任务。
- 文内文献引用形式、位置、上下标和字段保持，仅更新已授权的派生字段结果。DOI/URL 按字面保护，图表手写引用同步授权不适用于文献编号。

### 4.18 附录与索引

- 附录按实际标题级别，不强制新页。保留 A/B 或数字编号，正文序列与附录序列隔离，内部标题正常分级，正文继承正文格式；固定版式附录保持并进行视觉复核。
- 附录图、表、公式的独立序列按本任务明确规则处理，不擅自套正文序列。目录收录由大纲决定，页码连续，不能为加入目录而改变作者内容顺序或固定布局。
- 原稿无索引时不从正文自动创作索引。已有索引保留类型、条目顺序、分组、页码范围、“见”“另见”关系及分栏，不强制双栏。
- 索引标题按实际层级；条目宋体/Times New Roman、9pt、左对齐、最小 15pt、悬挂对齐，原悬挂量保持；层级明确时使用 0/2/4 字符层级缩进，未明确时保持并按需判断。
- XE/INDEX 字段及来源保持，只在最终阶段选择性更新获批派生页码结果。静态索引不伪称已更新；当其页码因排版失效时必须列为需要处理的问题，由用户决定核对、转换或保留并明确接受该限制，不能静默交付为正确页码。

### 4.19 术语、缩略语和符号表

- 标题按实际层级，保持已有段落或表格结构。段落式术语：术语宋体/Times New Roman、10.5pt、加粗，释义常规，最小 18pt；先确定术语和释义边界。
- 无有意义原布局且本次确认需要重建布局时，缩略语表采用无边框表、宋体/Times New Roman 9pt、最小 15pt、左对齐；符号表同字号行距，符号/单位居中、说明左对齐。
- 符号字形按 4.8 的语义范围处理。不提取生成、排序、翻译或修改术语、缩略语、符号及释义内容。

### 4.20 序跋、致谢、摘要和关键词

- 序、跋、致谢、后记的标题按实际级别，正文继承正文；已有签名和日期默认右对齐、宋体/Times New Roman、10.5pt、最小 18pt，明确不同的原布局保持，不重排复杂签名块；签名图片及内容顺序保持。
- 摘要标题按实际级别，已有行内标签保留。中文摘要宋体/Times New Roman、10.5pt、最小 18pt；英文摘要 Times New Roman、10.5pt，保持原缩进。
- 关键词标签和内容宋体/Times New Roman、10.5pt、加粗、左对齐、最小 18pt、首行缩进 0、段前 6pt、续行与关键词文字起点悬挂对齐；符号语义字形优先于整体加粗。
- 保持关键词分隔符、大小写、顺序和内容，不生成或翻译摘要/关键词。

### 4.21 字段与派生内容

- 登记字段位置、类型、代码、结果和关联，代码与结果分别保护。只更新本任务批准的字段及具体范围，禁止 update-all；不能因为字段类型常见就放行所有同类字段。
- 正式目录、标题/对象编号、页码和已确认交叉引用在本次规则明确的范围内可自动生成或更新，不逐个重复授权。PAGE、NUMPAGES、SECTIONPAGES、PAGEREF、已确认交叉引用等按 5.1 最终化；其他页面依赖字段须先确定用途和范围。
- 未知字段、日期/时间、外部链接、宏、数据源及其他不属于当前格式任务的载荷不自动刷新或执行。Word 打开、另存或导出造成的非目标变化同样必须纳入差异核验，不能仅证明脚本没有调用 update-all。
- 已有图表目录按确认的来源及范围更新；无此目录时不因存在图表就自动增加。派生标题来源不得带入图片或复杂对象。正文和字段中的实际引用目标始终保持。

### 4.22 编号、手写引用与格式例外

- 大纲确认同时确定标题编号方案；本任务需要统一图表编号时，在局部格式完成及标题编号确定后处理图表序列。已有正确编号不必无效重建；无号对象只有本任务明确要求编号时新增。图、表序列分开，跨章和附录的重启关系须明确；没有适用方案时保持并集中确认，不能由开发人员另造默认序列。
- 重新编号后，对唯一确定指向同一图表的手写引用自动同步编号部分。例如“见图3”中的“3”可以更新，句子其余部分和实际图对象不变。范围引用、多目标、跨章及重复编号先核对目标，歧义时暂停相关变更，不做全局数字替换。
- 公式、列表、文献、习题等其他编号的调整必须有各自明确任务依据，不能从图表授权类推。题注标签、说明文字和段落顺序不因统一编号而改写。
- 默认“同页”“三线表”等是适用格式要求，不能因实现缺失自动降级。少见的特殊原稿可由用户在看见位置、原因和影响后决定保留为具体格式例外；原有公式图片按 4.11 直接保持，不重复请求同类批准。工具引入的损坏不能接受为例外。

### 4.23 明确不继承的旧要求

| 旧要求或做法 | 本方案的确定处理 |
| --- | --- |
| 必须完整实现六层 Profile、类型/模块注册链才运行 | 只要求对象作用范围正确、规则结果明确、冲突可追溯；使用第 7 节的简单实现 |
| 所有作者空白一律不动；图表引用编号不得改 | 按第 3 节和 4.22 已授权范围整理与同步 |
| 仅接受可编辑公式、原稿公式图片一律阻断 | 4.11 保留原图并报告状态，禁止 OCR 重建及可编辑公式栅格化 |
| 全面标点校对、为每份任务建立完整领域符号表 | 按实际格式任务处理必要范围，不新增内容校对产品 |
| 每个对象、模块和已有决定均再次批准 | 有明确规则和已有决定时自动执行，真实疑问才提问 |
| 所有旧规则及属性逐项迁移、每条绑定专属 Schema/测试/迁移工件 | 仅实现本方案要求，以行为验证和必要来源记录追溯；旧规则未写入本方案即不生效 |
| 固定 V0.4.1—V0.4.4 链、强制至少五个 PR、全部旧门禁后才能启用 | 第 8 节三个集成阶段；按可审查范围提交，尽早贯通真实任务 |
| 到最后才测长文；强制 1000/2000 页两档；测试前逐项批准所有性能阈值 | 第 2、8、9 节目标 1000 页，第二阶段早测；按用户时间预期和实际瓶颈验证，不加入 2000 页门槛 |
| 每次交付全量重跑两遍并演练中断恢复 | 每份稿件执行实际核验；幂等与故障恢复按第 9 节开发验收和变化风险验证 |
| CLI/安装/agent 使用必须等旧完整版本链后另立方案 | 首阶段即提供 Codex 完整调用路径，末阶段提供必要安装与使用说明；其他 agent 后续扩展 |
| 本地任务记录一律不得含稿件文字或路径 | 可保存按需读取和问题定位所需的本地任务资料，遵守 6.3 的隔离边界；公开仓库和测试工件不包含私有稿件 |

本节新增的操作性后备值包括新建 TOC 项最小 18pt、无悬挂依据的非编号文献条目后备 2 字符、长文字表格单元格默认左对齐；它们明确写在本方案中，不伪称为旧方案已经冻结的值。未来改变这些外观选择时按第 10 节处理，不能只修改配置而不更新要求。


## 5. 整书运行流程及依赖

| 阶段 | 工作 | 输出及进入下一阶段的条件 |
| --- | --- | --- |
| 准备 | 保留原稿、检查环境，必要时转换 DOC，确定本次规则，完成全书对象清点和标题候选扫描 | 工作副本、输入核验基准和初始索引可用；转换差异已核验；精细分类在对应修改前完成 |
| 大纲确认 | agent 分批读取稿件，提出大纲，用户通过交流修正标题身份、层级和目录收录 | 大纲与必要例外确认并保存，不改写或重排作者内容 |
| 页面确认 | 根据全书布局风险清点，明确分节、前置与正文页码边界、页眉页脚及布局 | 影响全局布局的已知问题已决定；已有规则可自动采用，仅真实冲突和边界疑问需人工决定 |
| 批次排版 | 先书名与前置，再按章或对象批次处理正文、图表、公式等局部格式 | 每批内容检查通过，保存工作副本和恢复记录；局部疑问按依赖隔离 |
| 编号与关联 | 按确认大纲处理标题编号，再处理依赖章号的对象编号、引用及跨章事项 | 编号及引用对应一致，未决阻断项可见 |
| 目录与最终化 | 创建正式动态目录，在固定页面配置下由 Word 分页、更新获批字段并检查收敛 | 目录来源正确，连续两轮关键结果稳定，合法变化核验通过 |
| 整书检查与交付 | 核验内容、对象覆盖、结构、格式、字段和逐页版面，生成结果说明 | 无阻断项才交付合格 DOCX；否则保留待处理成果及原因 |

批次始终作用于同一完整 DOCX 工作副本，不物理拆章再拼接。每批只更新必要状态和检查点，不逐章重建全书正式目录或主动执行全书分页。局部图表排版不在全书阶段重复执行，只有依赖编号或跨章关系的工作后置。

全局样式和全书编号的影响范围必须如实记录，不能把全局变更伪装成局部批次。若人工修改大纲或规则，返回受影响阶段重做必要部分；不无差别从头重跑。

准备和页面阶段优先识别会影响全书决策的情况：超出栏宽的图表/公式、混合方向和分栏、前置编号边界、复杂页眉页脚，以及可能需要布局例外的固定版式。这里只做全书范围的必要风险清点，不要求先完成所有局部格式。已知的横向节和版心选择在批次执行前解决；后续新发现的问题按真实依赖返回上游，不因页面配置已确认而隐瞒问题。任务接入时也应尽早报告已能确定的打不开、转换损失或关键载体无法保持等阻断原因，避免长时间处理后才告知。

### 5.1 目录分页收敛

首次正式目录更新后，Word 重新分页并选择性更新获批页面依赖字段，形成第 1 轮结果。之后每轮依次更新目录、重新分页、更新获批字段，最多三轮。

连续两轮比较目录项数量、顺序、文字和页码，目录页数，正文起始物理/逻辑页，全书页数，各节页码配置及获批页面依赖字段结果。不能只比较总页数。

上述比较须逐项一致，每轮保留结果摘要与差异位置；文字可以使用精确文本的哈希比较，不能只比标题数量。段落同名但来源不同不合并；已授权字段也要检查实际引用关系和显示结果是否正确。

最终化不改变已确认分节、页码边界、起始值、编号格式或页眉页脚规则，不执行 update-all。三轮仍不稳定时停止并展示差异；需要改布局时显式返回上游阶段，不能在原循环中暗改配置或仅重置轮数盲试。

返回布局阶段后，只有规则、决定或有证据的修复发生实际变化，才启动新一轮最终化。相同问题和相同条件再次出现时停止该修复路径，展示已尝试操作和仍存在的差异；不能在“排版—检查—再排版”之间无限往返。首次默认自动执行及范围明确的修复无需逐次审批，涉及位置、内容权限或格式取舍时才交用户决定。

### 5.2 Word 临时副本和最终交付

全书最终化在同一整本工作稿派生的 Word 临时副本中进行，保留最后有效工作稿。临时副本与批次“同一完整 DOCX”的要求不冲突，不拆分章节、不拼接文档。未收敛、Word 失败或存在未授权差异时不覆盖有效稿。

优先复用选择性字段结果回写。若采用其他保存实现，必须证明最终候选只包含允许变化；不能把 Word 另存造成的任意差异一并接受。回写或另存后的实际候选还须在目标 Word 重新打开核验，确认字段、目录和分页与已通过的结果一致，不能只验证临时副本。

最终核验不顺手修复、刷新字段或改稿。检测到需要修改时回到相应阶段，修改后复核受影响结果；打开核验时若 Word 产生自动更新，也必须检测并重新核验。只读核验完成后才能标为可交付。

交付结论绑定实际交付文件的指纹、所用规则/决定版本、目标 Word 与字体环境、核验及渲染结果。最终稿在核验后发生任何变化，原结论不能继续沿用。该绑定使用一份简短任务结果记录即可，不建设签名或认证平台，也不把临时稿的检查报告当成最终稿的证明。

统一入口依据保存的任务状态提供合法下一步：准备 → 大纲确认 → 页面及批次处理 → 编号与关联 → 最终化 → 核验 → 可交付。疑问、失败及依赖变更允许返回必要阶段；未确认大纲、未完成必要处理或未通过核验不得越级取得完成状态。内部测试可单独调用脚本，但不能据此生成合格交付声明，不提供跳过内容保护或验收的完成选项。

## 6. 人工处理、长文上下文与恢复

Agent 不一次性接收千页全文或完整对象 JSON。工具保存全文索引、大纲、规则、决定和进度，按当前批次与跨章关系返回所需内容；上下文切换后从记录恢复。

大纲确认不等待所有细粒度对象分类和字符审计完成：先完成全书快速清点和候选标题覆盖，展示整书层级总览及需判断的标题，并可按章展开上下文。精细对象分析在实际执行前补齐；不得以此漏掉无样式、藏于表格/文本框或编号异常的标题候选。用户可以用一句决定处理同类标题，系统显示范围与例外，不要求逐条确认完整大纲。正式修改前仍须有有效大纲决定和对应保护基准。

疑问应显示原稿位置、必要上下文、问题原因、建议操作及适合展示时的预览。互动式、文字式都是可选形式，采用合理高效的方式，不建设两套系统以满足形式要求。按同一原因和适用范围合并问题，显示受影响对象与例外。

问题区分三类：用户意图不明、需要选择版式、工具处理失败。前两类给出上下文和可理解的影响，由用户决定后工具继续执行；工具失败先由开发/诊断流程处理，不要求用户回答技术细节，也不把失败伪装成排版偏好。只有确实需要用户参与的未决项进入用户问题清单，不把无关校对提示或已自动解决的警告全部混入。

局部问题只暂停相关对象和依赖工作；大纲、全书编号等全局问题暂停依赖阶段。用户决定按范围保存，不重复询问。用户接受保持原状可形成格式例外，但不能放行工具引入的内容破坏。

每批候选结果通过核验后才成为有效进度。中断时保留原稿和最近有效检查点；恢复时核对输入、规则、决定及工作副本身份。检测到外部修改时重新定位与核验，不能沿用失效记录继续写入。

### 6.1 对象覆盖与处理状态

对象记录必须同时覆盖识别成功、无法分类和只需保护的范围，并与原始 DOCX 包部件及关系清单核对。覆盖范围包括正文及前后置、段落和字符片段、样式和编号、分节与页眉页脚、表格/行/单元格、图片及媒体、题注、脚注尾注、OMML/EQ/OLE、字段代码与结果、书签与交叉引用、超链接、文本框、内容控件、批注和修订，以及未知扩展部件。

每个可独立修改或保护的对象保存稳定标识、位置和父子关联、输入核验基准、应用规则或保持原因、相关决定、所属批次、允许变化及结果。只保护的内部范围可以用范围摘要和包级清单表示，不强制每个 XML 节点建立独立审批和完整历史记录；但必须可定位差异，不能用父段落“已格式化”掩盖内部字段、符号或媒体未检查。

状态区分为待处理、已格式化并核验、按规则保持并核验、待人工判断、处理失败。按对象类别展示总数与各状态，说明分母，父子覆盖不能冒充同一层的去重对象总数。新生成的合法对象同样登记。

可交付时，所有应处理范围均为已格式化或已核验保持，无遗漏、待处理、未决疑问及未解决失败。未知对象只有在保持载荷、关联和必要显示得到验证时才能归入保持；无法验证则留作问题。用户明确接受的原稿格式例外可记录为保持，不能把失败改名或忽略损坏来凑覆盖率。

### 6.2 检查点与局部重做

每批记录输入和当前有效稿身份、规则与大纲版本、对象集合、必要决定、前置依赖、修改范围及核验结果。先写候选并检查，再原子提交有效检查点及一致状态；失败时保留前一有效版本，不能留下“状态已完成、文件未保存”的假进度。

恢复核对这些记录及工作副本，已完成且依赖未变的范围跳过；输入、规则或大纲改变时只使实际依赖范围失效，并明确全局样式或编号的影响。最终化中断的未验证结果不回写，可从最近有效整稿重新开始有界最终化，不能把不同轮次拼成一次通过。

MVP 保证恢复到最近有效进度，不额外承诺任意历史批次回退。至少保护原稿、最近有效工作稿、正在检查的候选及已有交付成果；不永久保留每批一份完整 DOCX。新检查点及状态完整落盘并验证可恢复后，才可轮换工具管理的过期临时副本，保留轻量处理记录；用户明确保留的中间稿不自动清理。不为节省磁盘先删除唯一有效检查点，也不预建复杂的增量文件存储系统。

### 6.3 本地任务资料与公开材料

本地任务目录可保存处理所需的稿件、索引片段、预览、决定和恢复数据，供 agent 按需读取；运行状态尽量使用对象标识、摘要和定位，不重复复制全书。该内部索引不是向稿件新增符号表、目录外文本或其他作者内容。

真实稿件、生成稿、渲染页、私有模板原文、敏感路径及具体私人问题上下文不写入公开仓库、公共日志或可公开测试工件。公开回归使用合成案例；用户授权提供的实际稿件可用于本地目标验收。面向所选 agent 的必要读取属于任务处理，不另外上传到无关服务。记录用于恢复的数据位置及清理方式，不擅自删除原稿或用户成果。

## 7. 实现结构与现有代码处置

| 职责 | 实现方向与复用范围 |
| --- | --- |
| Agent 调用与说明 | 更新现有 Skill 和统一入口说明；提供准备、按需读取、提交决定、批次执行、最终化、检查和状态能力，用户不需要直接操作内部配置 |
| 任务与对象记录 | 简单任务摘要加可查询本地对象记录，保存输入、规则、大纲、决定、批次及问题；初步选用标准库 SQLite 承载索引，避免反复处理数 MB 的整份 JSON |
| 格式执行 | 复用 `_common`、`structure_map`、`docx_pagination` 中已验证操作，分开识别、计划和修改职责；补限定空白整理和手写引用同步 |
| Word 与最终化 | 核验并完善现有 macOS Word 适配，复用并调整 Windows 更新器；分离布局确定、固定布局字段刷新与输出提交职责，复用 `field_writeback` 的选择性回写能力 |
| 核验与交付 | 复用现有内容、对象和格式审计以及目标 PDF 渲染，补实际页面异常记录、批次覆盖和精准允许变化核验 |

SQLite 是本方案的初始技术选择，不是产品硬性需求。若第一阶段证据表明更简单的分块文件结构已经满足查询、恢复和性能，可在不改变产品范围的情况下调整并记录理由。不得为此另建通用数据平台。

Agent 提交对象身份、规则选择、具体操作及必要决定；工具检查对象定位、操作前提、允许修改的属性与实际结果，再提交有效进度。使用几种具体、可验证的操作即可，不要求先设计通用操作语言。Agent 不通过重新生成整章正文完成格式化，新增执行脚本也不能绕过统一入口的核验。

已经符合本次规则的属性无需重写；可复用已确认分类和依赖未变的结果，只有歧义或新证据才重新请求 AI 判断。批次按章节/关联对象及实际成本组织，不逐对象另存整本书，也不预先锁定极小固定批大小。状态索引、检查点和 DOCX 保存的耗时及磁盘占用要纳入规模测量，不能为了“批次更细”使千页任务反复全量读写。

本方案是需求来源，默认配置是它的可执行表达，两者不能独立演化。维护一个当前配置；改格式值时同时更新方案对应条款和必要行为检查。以对象类别及用户可见结果组织少量验证案例，不为每个旧决策再建立一套注册、映射和审批工件。

保留现有仓库、通过测试的执行器及有用回归案例；重构 `run_monograph` 的阶段内部执行、`structure_map` 的多重职责以及 `finalize_docx` 的交付路径。默认模板与使用流程替换为当前版本。完整 v2 合同/注册表链暂停作为 MVP 前置，但保留历史成果，可按需复用小范围能力。

输出使用任务独立文件名和临时结果，保护原稿、已有成品及最后有效版本；验证成功才提交为可交付结果。不为首版承担多主体并发写入的全部对抗场景，但不能仅删除失败检查或任意覆盖文件。具体保存与恢复机制必须有相应测试。

## 8. 三阶段开发安排

初始工作树评估已完成；上传时发现 main 已有后续实现，第一阶段结合既有代码核对实际差距，不重新开启一轮无限延长的准备工程。以下三个阶段为集成里程碑，阶段内可以有合理提交或 PR，但不新增大量产品版本和审批节点。

阶段工作以代表性稿件和具体用户结果组织，不按第 4 节的条款顺序机械逐条开发。每类适用格式仍保留最终验收责任，但无相关对象的任务不加载额外分析；罕见类别的规则保持策略和真实处理能力要区分。选定小型整书、典型复杂稿、目标千页稿三类材料即可，不预建覆盖所有排列组合的样本库。已有可用实际材料尽早用于验证原稿复杂度，公开回归仍使用合成内容。

### 第一阶段：macOS 完整流程可用

先复用现有实现，用 DOCX 验证本机 Word 可靠打开、另存、分页、选择性字段更新、PDF 导出及最终稿重新打开的一条完整路径；同阶段尽早探测 DOC 转换是否保持内容和复杂对象。随后以代表性小型整书贯通当前规则、大纲交流、按需读取、对象决定、实际批次修改与恢复、编号目录、最终化和核验。第一阶段验证核心路径，各格式类别和主要载体的完整覆盖在第二阶段完成，不能把第二阶段全部功能提前堆入第一阶段。

Windows 在 macOS 基础操作接口得到实际验证后开始适配，第一、二阶段内完成必要实现，实机验收按第三阶段安排。未完成实机验证时明确状态；不同时探索两套未经验证的主流程，也不要求等 Windows 验收后才能展示 macOS 结果。上述安排只调整内部先后，不增加产品阶段、不取消 DOC 或双系统目标。

使用一份较小但完整的合成整书，包含标题、正文、图、表、公式、需要人工判断的对象，以及已授权的空白和引用操作。各项功能在同一任务中串联，不分别做孤立演示。

**验收出口**：通过 agent 从提交到交付真实 DOCX；Word 真实操作成功，内容保护和暂停恢复可检验，疑问可以定位、决定并继续。此阶段不宣称千页或两系统完整 MVP 已完成。

**首要验证**：旧工作树评估中的 macOS Word 探测曾在另存 DOCX 阶段失败，但上传时最新 main 已含后续 Word 最终化实现。第一阶段先核验并复用该能力，补足与本方案的差距，不重新开发已有可靠能力，也不把旧失败当成当前结论。接口字典、Word 已安装或模拟响应均不等于真实整书通过；不能以 LibreOffice 静默替代 Word 验收。

### 第二阶段：格式范围与复杂稿件可用

补齐第 4 节的格式范围及主要图表公式变体、前置、附录、注释等对象，完善跨章关联、分组判断、批次定位与恢复。逐项区分自动处理、规则要求保持、人工判断后工具可处理、尚未实现；最后一类不能作为完成。

使用逐步增大的复杂稿件，并在本阶段开始真实目标千页试跑。分开测量扫描、AI 阅读判断、写入、Word 分页、渲染和人工处理成本，依据实际瓶颈优化。

**验收出口**：主要对象有可执行路径，常见核心格式不大量依赖手工编辑；千页试跑结果、失败原因、内容保护及恢复证据可检查。不得把规模问题全部拖到最后阶段。

### 第三阶段：目标验收与交付

在 macOS 完成代表性复杂千页全流程验收，按用户安排进行 Windows 实机试运行和同范围验证；检查 WPS 基本使用情况。补齐最小安装和使用说明，修复核心任务阻断项。

**验收出口**：第 9 节条件满足，已知例外清楚可处理。macOS 已验证部分可先提供使用，Windows 未实测时标明待验证，两边通过才宣称双系统验收完成。达到条件即交付，不持续追加假设性的罕见组合。

## 9. 验收、测试与停止条件

| 验收项 | 要求与主要验证方式 |
| --- | --- |
| 核心任务 | 实际演示提交、确认大纲、格式处理、人工判断及 DOCX 交付，所有环节串联 |
| 内容保护 | 合法格式、空白和编号变更通过；注入范围外文字、数据、公式、媒体或引用目标变化时拒绝，并能定位差异 |
| 格式覆盖 | 本方案选定的格式有实现或明确的适用保持策略；不能将未实现功能改称 QA 或例外 |
| 对象与关联 | 保持图片、公式、嵌入对象、题注归属、脚注尾注及引用关系；图表保留原有前后文位置，核对文字—对象顺序和实际显示；包含浮动、混排及自然跨页案例，能检出载荷未变但对象被移位的错误 |
| 大纲与人工决定 | 分批提出大纲、保存决定、按共同原因处理问题；上下文切换后不无故重问或丢失决定 |
| 批次与恢复 | 在有代表性的检查点前后模拟中断，证明恢复不漏处理、不重复编号、不破坏最近有效结果 |
| 字段与收敛 | 获批字段正确更新，未知字段保持；稳定结果通过，第三轮仍变化时停止；分页循环不暗改布局 |
| 视觉 | 全书页面有渲染和检查覆盖，裁切、溢出、遮挡和不合理分页可定位并复核；不要求用户亲自逐页签字，也不宣称穷尽审美缺陷 |
| 规模与平台 | 真实复杂千页验收；两系统真实 Word 状态清楚，WPS 基本使用通过；不能用复制页面凑数或模拟 Windows 成功代替 |
| 时间 | 整书预期 1—2 小时，确需更长可以说明并调整；大纲确认控制在 20 分钟内、10 分钟内最佳；疑问处理以质量为先 |

记录端到端总耗时、自动处理、大纲确认、其他人工处理和等待时间，不能靠排除某一项来宣称达到预期。时间目标不授权省略检查或自动批准歧义。

每份稿件执行实际内容、格式、对象、字段和版面检查。重复运行稳定性与故障恢复主要在开发验收中验证，不要求每次交付都从头运行两遍或人为中断一次；新变化或实际异常触发针对性复验。

逐页视觉验收分为全页基础检查和问题页复核。所有最终 Word 页面须有可定位的渲染结果与检查状态；结合版面信息检查图表可见性、越界、遮挡、题注分离和异常空白等适用问题。疑似异常、浮动/混排等高风险区域及自动检查无法判断的页面进入详细视觉复核，必要时再向用户展示。不得把“PDF 已生成”当成“页面已检查”，也不把无人能实现的“自动证明所有页面完美”设为门槛。自动检查的适用范围、漏检风险和剩余复核范围必须如实说明，用户仍可重点检查排版。

开发验收中除耗时外记录人工问题组数、受影响对象数、重复提问及需要人工手工排版的范围，用于判断“大部分自动完成”是否属实。首轮实际材料用于建立测量基线，不编造通过率；若常见图表、公式或标题大量转交手工处理，应修复核心能力，不能仅凭对象状态闭合宣称 MVP 完成。

面向用户的交付说明只需包含成品位置、本次格式规则摘要、内容保护及图表位置核验结论、已接受的具体例外和可定位的检查入口。完整技术日志留作诊断，不要求用户阅读。未解决阻断项时交付的是待处理成果，不能标为合格；有已接受例外时明确写出，不与无例外的结果混淆。

已有测试按复用代码与风险保留。新测试验证实际行为和保护边界，避免只验证生成文件存在或逐字复制实现。修复失败后完成针对性回归及必要整体检查；没有新改动、新失败或未解决风险时，不重复扩展验证链。

关键保护检查不能只信任修改器自己的“已成功”记录或 agent 自报。对代表性案例，预先给出允许的变化、应保持的文字/图表顺序及引用目标，再核对实际输出；加入文字被误删、图片载荷未变但位置移动、编号更新指错对象等有明确预期的反例。可以复用解析工具，但验收预期不能从同一份修改结果反向生成。这是检查方法的要求，不要求常驻第二个 agent 或新审批角色。

必须解决内容破坏、主要格式失败、核心流程阻断和代表性千页无法处理的问题。罕见且能安全保持、定位并合理人工处理的情况可以后置；发现安全问题必须阻止不可靠结果交付，但不要求为每种罕见输入实现自动修复。限制若使常见核心任务不能完成，仍然阻断 MVP。

## 10. 开发边界、变更与经验总结

用户明确允许在方案完善和整个开发过程中随时提问、反问和提出不同意见。遇到需求歧义、相互冲突的要求、内容保护边界不清、实测结果不支持既定设想或必须由用户决定的取舍时，及时说明具体事实、影响和建议，并提出聚焦的问题；尽量让用户用自己的话表达，不要求用户代替开发者决定内部技术细节。

提问不等于停止全部工作：依赖答案的部分等待决定，无关且已有授权的工作继续推进。已有明确要求、已保存的决定和范围内的合理实现选择不重复询问；等待时长不视为回答或授权。该协作许可不等于对本方案全部建议、业务代码开发范围、合并或发布的额外批准。

正常实现和局部修复在当前阶段内推进，不为每个字段、脚本或 Schema 重新确认需求。每阶段集中展示一次可运行结果、验证证据、已知限制和下一步。

改变目标、内容修改权限、格式范围、关键使用方式或验收标准时，明确说明依据、影响及建议，获得相应确认后更新本方案。实现方式在相同目标和边界内的合理优化，记录理由及验证即可，不额外扩大审批链。

新增框架、抽象层、注册表或大量验证工件，需要指出当前问题及更简单方式为何不足。不存在的未来需求不自动成为开发任务。不得通过删检查、扩大忽略范围或降低验收口径伪装完成。

同一轮开发只维护一个当前集成目标及必要工作项，后续优化留在简短待办中，不随发现随插入主线。先修阻断项及影响面，再处理可后置问题；连续修复未带来新证据或改善时，停下诊断根因，不继续叠加补丁。满足阶段出口后进入下一阶段，满足 MVP 出口后交付。

阶段结束或出现实质问题时简短记录事实、原因、最小改进和验证结果。优先改进重复修改、无效测试、重复询问、处理耗时、内容保护和排版正确性。假设与已验证结论分开，效果不佳的做法允许修正或撤回。经验落实到流程、代码或测试，不仅积累文档。

本方案保持固定文件入口，通过版本控制和简短修订记录追溯变化，不不断追加相互覆盖的方案附录。需求确认记录和技术证据有各自用途，不成为并行实施权威。

方案审查只因具体冲突、遗漏的核心要求或验证证据而修改正文；已有规则能够覆盖的问题直接使用，不为每次讨论新增一套门槛。方案已整体确认，后续先稳定产品要求，在阶段内验证技术假设；方案完整不等于技术可行性已证明。Word 自动化、复杂载体保护、千页成本和人工判断量必须用第一、二阶段的实际结果回答，不能继续靠增加文字保证。
