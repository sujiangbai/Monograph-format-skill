# format-monograph 跨 Agent Skill 建设方案 V0.1.0

状态：已批准基线

## 目标

建设适用于多数 Agent 的专著 DOCX 格式处理能力包。核心遵循开放 Agent Skills 规范，不依赖 Codex、Claude 或其他单一平台。

首批兼容目标为 OpenAI Codex、Claude Code、Gemini CLI、VS Code / GitHub Copilot。V1 只修改格式和经过批准的派生字段，不修改正文措辞、事实、数据或引用内容。

## 架构

- `format-monograph/` 保存纯开放标准核心。
- `adapters/` 保存平台安装和发现适配。
- `docs/` 保存治理、兼容矩阵和不可覆盖的方案快照。
- `tests/` 保存合成测试和兼容性验证。
- 核心脚本使用跨平台 Python，不依赖 shell 专用语法、Word COM 或 Agent 私有 API。

## 规则模型

格式资料可来自 DOCX、PDF、图片或文字。提取优先级为：

1. 书面要求。
2. DOCX 模板。
3. 样书或截图。

规则统一写入 `format-profile.json`，包含版本、适用范围、来源、规则编号、语义对象、格式属性、依据摘要、置信度、批准状态、冲突和未决 QA。原始出版社材料默认不进入公开仓库。

## 工作流

1. 检测 Agent 和本机能力。
2. 读取格式资料并生成规则草案。
3. 向用户展示冲突、缺失项和 QA。
4. 仅在用户确认后盘点并修改书稿。
5. 保留原稿，应用批准规则。
6. 验证正文内容一致性。
7. 渲染并逐页检查。
8. 交付干净稿、审阅标注稿和格式报告。

允许刷新目录、页码、标题编号、题注编号和交叉引用。资料未覆盖的对象保持原状，不允许自行猜测。

## 能力降级

- 完整模式允许交付完整三件套。
- 结构模式需要用户明确接受未完成视觉验收。
- 分析模式不得声称修改或验证了 DOCX。
- 缺失字体不得静默替换，必须进入 QA。

## 验收

- 使用开放规范验证器检查 skill。
- 在四个首批平台验证发现、触发、引用加载和脚本调用。
- 用合成 DOCX 覆盖分节、横竖页、目录、标题、页眉页脚、图表、公式、脚注尾注、参考文献和附录。
- 验证原稿不被覆盖，正文内容除批准派生字段外保持一致。
- 对干净稿和审阅稿逐页渲染。
- 平台无账号或授权时标记“待实机验证”，不得误报通过。

## 实施阶段

1. 建立许可证、治理和 V0.1 基线。
2. 实现开放标准 skill、规则模型和环境检测。
3. 实现 DOCX 盘点、配置验证和内容保护。
4. 实现格式应用、审阅标注、报告和渲染。
5. 实现四个平台的轻量适配与兼容测试。
6. 接收首批资料，经 QA 建立真实规则配置。
7. 用真实专著进行端到端迭代。

## 已确认约束

- GitHub 是源码和方案的唯一持久化位置。
- 待修改文件仅为 DOCX；格式依据可来自 DOCX、PDF、图片或文字。
- Microsoft Word 2016/2019/2021/365 是主要文档兼容目标。
- 核心 skill 应能在 Windows、macOS 和 Linux Agent 环境运行。
- 任何方案变化必须创建新版本方案文件并走分支、PR 和用户审批。
