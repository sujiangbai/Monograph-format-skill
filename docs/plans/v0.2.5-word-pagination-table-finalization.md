# format-monograph V0.2.5：Word 自动终稿、双分节页码与表格视觉格式

## 背景与目标

V0.2.4 的真实单章试排已经能够建立可编辑目录字段、稳定标题映射、人工图表编号、图表分页绑定和内容保护，但终稿仍有四类不足：

1. 目录和页码只能标记为 `deferred`，调用者还要在 Microsoft Word 中手动更新字段。
2. 启用奇偶页不同时只建立了默认页脚，没有建立偶数页页脚，导致偶数页页码缺失。
3. 目录迁移和尾部分节删除同时执行时仍存在定位与审计误报。
4. 数据表目前主要处理分页，列宽、单元格边距、对齐、边框和复杂表格溢出尚未形成可执行规则。

V0.2.5 的目标是让具备 Microsoft Word 的 Windows 环境可以交付“打开即正确”的可编辑 DOCX，同时保持核心 Skill 对其他 Agent、操作系统和字段后端开放。没有 Word 的环境必须正确降级，不得伪造已经更新的目录或页码。

## 权威规则

1. 当前调用者在每次任务中提出的明确格式要求仍具有最高任务级优先级。
2. 本技术教材配置采用以下页码基线，后续调用者可以明确覆盖：
   - 目录部分独立分节，目录第一页显示阿拉伯数字 `1`，随后连续编号。
   - 正文部分另起分节，正文第一页重新显示阿拉伯数字 `1`。
   - 正文后续各章、普通分节和横向分节继续编号，不得逐章重启。
   - 奇数页和偶数页均显示页码；镜像版式中奇数页置右外侧，偶数页置左外侧。
   - 目录第一页和正文第一页均显示页码，不再沿用 V0.2.4 候选配置中的“章首页隐藏可见页码”。
3. 页码、目录和交叉引用必须保持真实 Word 字段，不得写成静态文本或图片。
4. 原稿永不覆盖；Word 自动化、字段刷新和 PDF 导出只操作派生副本。
5. 正文、表格文字、注释、引用、答案、公式、嵌入对象和媒体继续受完整性保护。

## 跨平台字段后端

### 通用后端协议

核心脚本不得直接依赖 Word COM、PowerShell、`pywin32` 或绝对路径。扩展 `finalize_docx.py`，支持一个通用外部字段后端协议：

```text
finalize_docx.py <formatted.docx>
  --profile <profile.json>
  --structure-map <map.json>
  --output <finalized.docx>
  --field-updater auto|external|libreoffice|deferred
  [--field-updater-command <command>]
```

外部后端通过 JSON 输入输出接收源副本、目标副本、允许更新的字段类型和目标软件，返回后端名称、软件版本、更新对象数量、重新分页状态、保存状态及可选 PDF。核心在接受输出前必须重新执行内容、字段代码和受保护对象审计。

### Microsoft Word 适配器

在 `adapters/microsoft-word/windows/` 提供可选适配器，不把 COM 调用放入开放 Skill 核心。适配器应：

1. 检测 Windows、Microsoft Word 安装和可自动化状态。
2. 复制输入稿后，以隐藏窗口打开派生副本；禁用宏、外部链接更新、最近文件记录和交互提示。
3. 使用 Word 排版引擎重新分页。
4. 更新主文档、目录、页眉页脚、脚注尾注和其他 story ranges 中已批准的 `TOC`、`PAGE`、`REF`、`PAGEREF` 等字段。
5. 更新整个目录而不是只更新页码。
6. 保存为 DOCX，重新打开并确认字段缓存存在、字段代码仍可编辑。
7. 可选导出 PDF，供目标软件逐页视觉检查。
8. 无论成功或失败都关闭文档和 Word 进程；不得遗留锁文件或后台进程。

只有 Word 后端完成保存、字段缓存检查、内容审计和受保护对象审计后，状态才可标记为 `refreshed_target_word`。若还能使用 Word 导出的 PDF 完成逐页检查，可标记 `target_layout_verified`。

### 降级

- 没有 Word 或用户未授权目标软件自动化时，允许使用 `deferred`，但必须明确提示仍需更新。
- LibreOffice 继续作为渲染器和可选字段候选；若刷新导致字段代码、标题、正文或受保护对象变化，必须拒绝结果。
- 不允许用静态目录、预估页码或 LibreOffice 分页结果冒充 Word 最终结果。
- Word 自动化失败时保留失败副本和状态报告，不覆盖最后一个通过审计的稿件。

## 目录与正文双分节页码

结构映射升级为 `1.4`，读取端继续兼容 `1.0` 至 `1.3`。新增 `pagination_sections`：

- `toc_start`：已批准目录起始定位器。
- `body_start`：正文首个章题或正文起始定位器。
- `number_format`：本配置为 `decimal`。
- `start_at`：目录和正文均为 `1`。
- `continue_after_body_start`：正文后续所有分节为 `true`。
- `odd_position` / `even_position`：镜像版式分别为 `outer_right` 和 `outer_left`。
- `show_on_first_page`：目录和正文均为 `true`。

执行时必须：

1. 在正文开始前创建真正的“下一页分节符”，不能用分页符模拟。
2. 在目录分节设置 `w:pgNumType start="1" fmt="decimal"`。
3. 在正文首节再次设置 `start="1"`。
4. 后续章节、横向表格和其他正文分节删除错误的 `start`，保持连续。
5. 启用 `evenAndOddHeaders` 后，为每个独立页脚关系同时建立 `default` 和 `even` 页脚；奇数页右对齐、偶数页左对齐。
6. 不使用 `titlePg` 隐藏目录或正文第一页页码；若其他前置页需要隐藏，必须单独 QA。
7. 检查每个保留分节的页脚继承关系，防止横向分节、删除空节或“链接到前一节”造成页码消失或重启。
8. 在 Word 刷新后验证目录页码序列和正文页码序列都从 1 开始，正文内部不存在非批准重启。

报告不得把 DOCX 包内 `PAGE` 字段数量当作实际页数。验收必须基于 Word 重新分页后的页序列或导出 PDF。

## V0.2.4 稳定性修复

### 尾部分节顺序与定位

- 分节边界增加文本哈希、前后上下文哈希和节属性哈希，不再只依赖源段落序号。
- 安全尾部分节应在物理删除静态目录之前处理，或在目录迁移后通过稳定定位器重新解析。
- 删除必须从末节向前执行，并保持最后一个有效分节的页边距、方向、页眉页脚和页码规则。

### 目录锚点归一化

- `legacy_toc_empty_anchors` 只适用于确实产生旧空锚点的 1.0 至 1.2 输出。
- 1.3 及以上物理目录迁移不得把目录后的合法空白分隔段认作旧锚点。
- 合成测试必须同时覆盖合法空白段保留和旧输出兼容。

### 孤立页眉页脚部件

- 删除分节后检测不再被任何保留分节引用的页眉页脚关系。
- 可以安全删除完全孤立的页眉页脚部件及其关系和内容类型；若保留，则内容指纹必须忽略这些不可达部件。
- 仍被任一分节引用的部件不得删除或忽略。
- 审计报告列出清理数量，不输出页眉页脚正文。

## 表格视觉格式

表格结构映射和配置增加可逐表批准的视觉属性：

- 表格可用宽度、对齐方式、首选列宽和是否允许自动调整。
- 单元格上下左右边距、垂直对齐及按列角色设置的水平对齐。
- 表头字重、底纹和边框；正文中西文字体、字号及固定行距。
- 三线表、全框线和保留原边框三种明确预设。
- 数值列、小数点、单位列、短代码列和叙述列的不同对齐策略。
- 续表、重复表题/表头、跨页拆行和超高行例外。
- 宽表是否进入横向分节，以及横向分节前后的页码连续性。

安全规则：

1. 布局表、图片容器和教学提示框不套用数据表视觉格式。
2. 复杂合并单元格、浮动对象或无法确定列角色的表格只报告并生成 QA。
3. 不通过缩小到不可读字号解决溢出；优先调整列宽、单元格边距、换行或经确认后使用横向分节。
4. 可见换行符、控制符或疑似源格式标记只报告，未经确认不得删除。
5. 表格视觉修改后必须重新检查文字、合并关系、行列数量和媒体载荷完全一致。

## 脚本、适配器与文档变化

- 新增 Microsoft Word Windows 适配器及安装、授权、发现和安全说明。
- 扩展 `check_environment.py`，分别报告 `word_automation`、`word_field_refresh` 和 `word_pdf_export`。
- 扩展 `finalize_docx.py`，支持外部字段后端协议及 `refreshed_target_word`。
- 扩展 `inspect_docx.py`，盘点目录/正文边界、页码重启、奇偶页脚、首页不同和页脚缺失。
- 扩展 `structure_map.py` 和 `validate_structure_map.py`，支持结构映射 1.4。
- 扩展 `apply_profile.py`，执行双分节页码、奇偶页脚、表格视觉属性和稳定分节清理。
- 扩展 `audit_docx.py`，验证页码分区、偶数页页脚、不可达页眉页脚和 Word 字段缓存。
- 扩展 `render_docx.py`，允许使用 Word 导出的 PDF 作为目标软件视觉依据。
- 更新 `SKILL.md`、能力分级、结构映射、QA 报告、技术教材配置和相关适配说明。

核心 Skill 仍不得包含真实书稿、本地路径、Agent 私有提示或 Word COM 代码；Microsoft Word 调用只存在于可选适配层。

## 测试与验收

使用完全合成的 DOCX 验证：

1. 一页和多页目录均从阿拉伯数字 1 开始。
2. 正文第一页重新从 1 开始，后续章节和横向分节连续。
3. 奇数页、偶数页和正文第一页均存在可见 `PAGE` 字段。
4. 启用奇偶页不同时，缺少 `even` 页脚必须审计失败。
5. 目录字段经模拟外部后端更新后仍可编辑，缓存条目与批准标题一致。
6. Word 后端不可用、拒绝授权、更新失败和被保护视图阻止时正确降级或阻塞。
7. 外部后端修改正文、字段代码、公式、媒体或嵌入对象时拒绝输出。
8. 尾部分节与静态目录同时处理时不再依赖变化后的固定段落序号。
9. 1.3 新目录后的合法空白段不产生内容误报，旧空锚点仍可兼容。
10. 孤立页眉页脚部件被安全清理或规范化，仍被引用的部件保持。
11. 数据表列宽、边距、对齐、边框和重复表头符合批准配置。
12. 复杂合并表、布局表、超宽表和可见控制符生成正确 QA。
13. Word 导出 PDF 时逐页检查目录、页码、表格、图题、重叠、截断和尾部空白页。
14. 没有 Word 的 GitHub Actions 使用协议模拟器测试核心；Word 实机测试明确标为独立环境验收。
15. Windows、macOS、Linux、四个首批 Agent、Agent Skills 规范及全部既有测试继续通过。

真实书稿及 Word 导出的页面只用于用户本地验收，不进入仓库、日志、Actions 工件或 PR 描述。

## 实施顺序与治理

1. 从最新 `main` 创建 `plan/v0.2.5-word-pagination-table-finalization`，新增本方案并更新索引。
2. 方案 PR 完成 QA 并获得用户明确批准后 squash merge。
3. 从新的 `main` 创建 `skill/word-pagination-table-finalization-v0.2.5`，实现跨平台核心、合成测试和 Microsoft Word 可选适配器。
4. 实现 PR 完成自动测试与独立 QA，获得明确批准后 squash merge。
5. 使用合并后的实现重新处理本地单章；先用 Word 自动刷新，再用 Word PDF 和 LibreOffice 分别渲染并比较。
6. 用户确认单章目录、双分节页码和表格效果后，再对整本书执行一次性处理。
7. 任何后续方案变化继续创建更高版本文件，不覆盖本方案或旧方案。
