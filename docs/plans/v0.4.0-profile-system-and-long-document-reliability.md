# format-monograph V0.4.0：Profile 分层与长文可靠性总体方案

## 1. 定位与范围

V0.4.0 重新划分格式规则的权威来源、Profile 职责和整书完成条件，解决旧 technical-textbook 候选规则同时承担安全、书籍类型、教材功能和任务默认值所造成的冲突，也为千页级 DOCX 的可恢复处理建立统一验收模型。

本方案是后续 V0.4.1 至 V0.4.4 的总体设计，不是实现 PR。本方案不开发代码，不创建正式 Profile，不修改脚本，不发布版本，不封装 CLI，也不宣称已经具备千页级可靠处理能力。

## 2. 格式权威与安全不变量

### 2.1 格式来源优先级

运行时采用以下不可变的决议顺序：

1. **安全不变量（不可覆盖）**；
2. 当前用户/任务的明确覆盖及后续 QA 决定；
3. 用户指定适用于本次任务的出版社要求或 DOCX 模板；
4. 已批准且只在自身语义对象范围内生效的功能模块；
5. 用户选择的书籍类型 Profile；
6. `monograph-base`；
7. GB/T 等标准，仅用于以上各层未覆盖项目的补缺。

功能模块不是全局覆盖层。`textbook-pedagogy` 只能作用于习题、答案和教材教学提示，`equation-heavy` 只能作用于公式密集对象，`engineering-drawing` 只能作用于工程图纸及其标识，`code-heavy` 只能作用于代码和算法对象。模块越界的属性不参与合成；多个已批准模块对同一语义对象的同一属性给出不同值时，必须进入 QA，不得按模块数组顺序、加载顺序或最后写入决议。

样书、截图、OCR 和推断只能形成带来源、置信度和确认状态的候选证据，不自动取得上述层级。更高格式层覆盖较低格式层时必须记录覆盖链；同层冲突、来源适用关系不明、属性缺失、低置信度或对象无法分类时必须报告并进入 QA，不得静默选择。

### 2.2 独立安全层

安全不变量不属于格式优先级，任何用户要求、模板、Profile 或标准都不能覆盖：

- `format-monograph` 不执行一般内容编辑。文字、标点、事实、数据、公式语义、题注文字、答案和参考文献内容始终不得由本 Skill 修改；内容问题只报告，需要编辑时转交本 Skill 之外的独立工作流。
- 不覆盖原稿；所有应用、字段更新、渲染和恢复均操作派生副本。
- 不破坏或静默替换公式、图片、媒体、OLE/MathType、OMML、字段、书签、交叉引用、批注、修订、脚注、尾注、文本框、内容控件及其他嵌入对象。
- 公式保持可编辑；不得把公式栅格化为图片。
- 不绕过内容、结构、字段、目标 Word、逐页视觉、幂等性和恢复审计。
- 无法证明安全时保持原状并报告，不以“格式统一”为理由猜测或删除。

允许变化只限于受控结构变化：经批准删除并重建标题编号前缀；经批准生成或更新 Word 派生字段结果；经批准的目录、页码、交叉引用及其他派生结构。每项变化必须进入允许变化清单、对象哈希和字段审计；未列入清单的变化一律拒绝。

安全层只定义保护、允许变化清单、审计和交付门禁，不提供书籍外观默认值。

## 3. Profile 分层架构

### 3.1 六层模型

| 层级 | 责任 | 允许内容 | 禁止内容 |
| --- | --- | --- | --- |
| 安全层 | 保护原稿、作者内容和复杂对象，限定可变范围及验收门禁 | 内容指纹、对象保护、审计、失败策略 | 版式偏好和可被覆盖的外观值 |
| `monograph-base` | 提供可独立使用的专著基础格式 | 书名、前置部分、目录、普通标题、正文、页码、通用图表、注释、引文、参考文献、附录、索引及保守布局策略 | 理工科符号细则、教材习题样式、出版社专属值 |
| 书籍类型层 | 只增加特定领域规则 | `science-engineering-monograph` 的科学符号、公式领域规则、工程表格/图纸、理工科对象编号和专业符号表 | 重复整套基础格式、安全规则降级、任务特例 |
| 功能模块层 | 按书稿实际语义对象选择附加能力 | `textbook-pedagogy`、`equation-heavy`、`engineering-drawing`、`code-heavy` 各自范围内规则 | 未批准时生效、越界覆盖、按顺序解决模块冲突 |
| 出版社/模板层 | 表达用户指定出版社要求或模板的适用规则 | 可公开的规则摘要、模板映射、来源定位 | 未授权原文、样书内容、本地路径 |
| 任务/用户覆盖层 | 表达当前任务明确要求和 QA 决定 | 属性覆盖、例外对象、批准变更 | 突破安全不变量 |

`monograph-base` 在不选择任何书籍类型或模块时，必须仍能独立生成符合本方案冻结值的基础专著格式。类型层的正式 ID 为 `science-engineering-monograph`，显示名为“理工科专著”，只增加科学符号语义、公式领域规则、工程表格/图纸、理工科对象编号和专业符号表。教材习题、答案和教材教学提示进入可选 `textbook-pedagogy`；`equation-heavy`、`engineering-drawing`、`code-heavy` 只覆盖各自语义对象。模块只能在用户选择或对象证据充分并经 QA 批准后启用。

### 3.2 扁平化最终 Profile

执行前必须把选定层合成为一个只供本次任务使用的扁平化最终 Profile。每个最终属性至少记录：

- 语义对象、属性和值；
- 最终来源层、来源 ID 和证据摘要；
- 从低到高的候选值与完整覆盖链，包括模块作用域验证；
- 冲突类型、处理结果、用户 QA 决定及确认状态；
- 置信度、适用范围和例外对象；
- 是否允许自动应用、仅报告或阻塞执行；
- 安全不变量检查结果。

合成结果不得包含出版社规范全文、私有书稿文字、本地路径或未授权材料。任何未解决冲突、模块同属性冲突、必要属性缺失、低置信度自动规则或无法分类对象，都必须进入冲突/缺失/QA 清单；不得通过数组顺序、最后写入或 Agent 自行判断静默胜出。

## 4. Profile 资产与私有证据边界

- 旧 `technical-textbook-layout*` Profile 全部保留为历史候选及迁移测试输入，不直接改名、删除，也不默认为 `monograph-base` 或“理工科专著”。
- V0.4.2 应从旧候选逐条提取可迁移规则，明确标记为保留、修改、移层、拆分或废弃，并以新 ID 输出；不得让新旧 Profile 同时自动生效。
- 私有科学符号规范只能形成不含原文、本地路径、截图、样书文字或私有哈希的规则摘要，并记录“私有来源、非公开、待任务确认”。
- 私有科学符号规则只允许进入 `science-engineering-monograph`；`monograph-base` 只负责识别、保护和分类科学符号。
- 仓库不得宣称私有符号规范当前具有强制法律效力；GB/T 等标准也只在本方案定义的最低补缺层使用。

## 5. 规范性冻结格式与决策追踪

本节是 V0.4 的规范性附件，不是示例。每个决策均给出稳定 ID、语义对象、精确默认值或保持策略、归属、允许覆盖来源、执行模式、安全条件、预计实现版本、必需测试和旧规则迁移。表中“用户/出版社”表示只有当前用户/任务及后续 QA，或用户指定出版社要求/DOCX 模板可以覆盖；已批准功能模块仅能在自身语义对象范围内覆盖；任何来源均不能覆盖安全不变量。

执行模式含义：`自动` 表示对象分类和前置条件均确定时可自动应用；`保持` 表示默认不改并审计；`QA` 表示必须先确认；`报告` 表示只报告且本 Skill 不修改；组合模式按最严格条件执行。

## 6. 旧 technical-textbook 总体迁移要求

旧 `technical-textbook-layout*` 只作为历史候选和迁移测试输入。V0.4.2 必须逐个旧规则生成“保留、修改、移层、拆分或废弃”映射，新旧 Profile 不得同时自动生效。第 5 节每个决策的“旧迁移”列是规范性迁移入口；未出现的旧属性也必须列入 V0.4.2 的逐属性迁移报告，禁止只写“兼容旧版”。

旧 Profile 中的内容保护、公式可编辑、原稿不覆盖和字段保持可编辑进入安全层；普通专著外观进入 `monograph-base`；科学符号、工程图纸和理工科对象规则进入 `science-engineering-monograph` 或相应模块；习题、答案和教材教学提示进入 `textbook-pedagogy`。旧比例边距、固定行距、强制章前分页、Arial 标题、四级宋体、前置罗马页码、章首页隐藏页码、自动缩小长引文、索引强制双栏、强制楷体单元格提示框等冲突值不得成为新默认。

## 7. 确认后的整书处理流程

固定处理顺序如下，后续实现不得重新排序：

1. 确认格式来源与优先级，合成扁平化最终 Profile。
2. 建立最终语义目录和覆盖全文全部对象的台账。
3. 确认页面与分节布局。
4. 处理书名与前置部分。
5. 在同一 DOCX 中按章或对象批次处理。
6. 根据最终语义目录重建标题编号。
7. 处理图、表、公式、注释、附录等对象。
8. 创建并首次更新正式目录字段。只使用批准语义标题生成动态 TOC；这是首次目录结果，尚不能认定页码最终正确。
9. 在目标 Microsoft Word 中执行第一次全书重新分页，并选择性更新获批的页面相关字段，包括 PAGE、NUMPAGES、SECTIONPAGES、PAGEREF、交叉引用及其他页面依赖派生字段；不得执行 update-all。
10. 再次更新正式 TOC，随后重新分页并重新更新获批的页面相关字段，执行分页与目录收敛验证。若结果变化，重复“更新 TOC → 重新分页 → 选择性更新页面依赖字段”，但包括第 9 步形成的第 1 轮在内，默认总轮数不得超过 3 轮。
11. 收敛通过后再执行内容、结构、格式、字段、目标 Word、逐页视觉、幂等性和恢复验收。

每章或对象批次完成后，只更新结构清单、对象状态、保护哈希和原子检查点。不得每章重建全书正式目录或触发全书分页，也不得物理拆分 DOCX 后重新拼接；所有批次始终作用于同一受控工作副本。

第 3 步页面/分节阶段负责确定页码系统配置，包括前置部分从 1 开始、正文独立从 1 开始、后续正文连续、奇偶页页码位置和章首页规则。第 9 至第 10 步只负责在既定配置下由目标 Word 重新分页和刷新白名单内字段结果，不得在收敛循环中新增、删除或重建分节，也不得改变页码起始值、编号格式或页眉页脚规则。

## 8. V0.4 长文可靠性模型

### 8.1 全对象台账与覆盖证明

`prepare` 的后续实现必须遍历并登记全部可寻址对象，而不是只记录识别成功对象。对象至少包括文档/分节、段落、标题候选、列表、表格及单元格、图片和绘图、公式和嵌入对象、题注、脚注尾注、字段、书签、交叉引用、批注修订、文本框、内容控件、页眉页脚、附录和后置部分。

每个对象必须且只能处于以下状态之一：

- `approved`：已分类并获准处理，尚待或正在进入格式阶段；
- `formatted`：批准规则已应用且对象级审计通过；
- `unchanged`：明确决定保留原状并完成保护验证；
- `blocked_qa`：缺少决定，保持未改并阻塞相关范围；
- `failed`：处理或验证失败，记录失败原因并隔离。

正式完成前必须证明：

`formatted + unchanged + blocked_qa + failed = 全部对象`

且 `approved` 数量为 0。`blocked_qa` 或 `failed` 可以存在于阶段报告，但存在关键项时不得标记整书完成。台账同时记录规则覆盖率、对象覆盖率、失败原因、未触达对象和分母定义；任何“未处理但未报告”都使验收失败。

### 8.2 批次、检查点与恢复

- 按章或同类对象建立有限批次，每个批次有输入指纹、最终 Profile 指纹、对象集合、前置条件、允许变更、结果和审计摘要。
- 批次提交采用原子检查点：只有应用和对象级审计全部通过才推进检查点；失败时丢弃该批次候选，不污染已完成批次。
- 后续实现支持 `--resume`，从最后一个通过审计的检查点继续；输入、Profile 或上游结构变化时只使依赖批次失效。
- 已完成且依赖未变的批次不得重复处理；恢复过程必须验证检查点链和当前工作副本一致。
- 日志和状态文件只保存结构 ID、状态、规则 ID、非敏感哈希、计数和错误类别，不保存书稿文字或对象载荷。

### 8.3 字段与最终验收

全书字段只在对象格式基本完成后统一最终化。语义目录、标题编号、附录/对象序列、定理/例题等序列、交叉引用关系以及可选图表目录/索引来源必须先完成并通过审计；随后创建和首次更新正式 TOC，再进入目标 Word 分页/目录收敛循环。首次 TOC 只是第 1 轮输入，不能作为最终页码证据。

每轮按“更新正式 TOC → 目标 Word 全书重新分页 → 选择性更新 PAGE、NUMPAGES、SECTIONPAGES、PAGEREF、获批交叉引用及其他白名单内页面依赖字段”执行，不得 update-all。第 1 轮使用首次 TOC；第 2 轮再次更新 TOC 后执行完整流程。若两轮结果不同，执行第 3 轮。

每轮必须保存不含书稿文字的结构化收敛快照，并与上一轮逐项比较。目录条目文字必须按每条完整显示文本精确比较；持久化快照只保存逐条文本哈希、顺序和计数，不保存目录文字本身：

- 目录条目数量、顺序和文字；
- 每个目录条目的页码；
- 目录总页数；
- 正文起始物理页和逻辑页码；
- 各节页码起始值和编号格式；
- 文档总页数；
- PAGE、NUMPAGES、SECTIONPAGES、PAGEREF 等获批页面依赖字段结果。

只有连续两轮上述结果完全一致才算收敛。默认最多 3 轮；第 3 轮后仍有任一差异时，状态必须为 `blocked_qa`，不得继续猜测、选择性回写不稳定结果或宣称整书完成。所有循环只在一次性目标 Word 临时副本中运行；收敛后仍须通过允许变化、对象哈希和字段差异审计，才能受控回写获批字段结果。

LibreOffice 和 PDF 只能用于补充渲染或视觉排查，不能替代 Microsoft Word 的最终重新分页和收敛验收。阶段性批次通过、首次 TOC 成功或单轮字段更新都不等于整书完成。未通过目标 Word 收敛、整书逐页视觉 QA、内容与对象保护、字段一致性、幂等性和恢复测试时，只能报告具体阶段通过，不得宣称整书已完成或可直接出版。

## 10. 测试门禁

### 10.1 Profile 系统

- 多层同一属性覆盖、同层冲突、缺失属性、低置信度、未分类对象和用户 QA 决议测试。
- 扁平化顺序无关且结果确定；每个最终属性能回溯完整来源和覆盖链。
- 安全不变量无法被任何层覆盖。
- 旧 schema/Profile 只作为显式迁移输入，不会隐式成为新基础层。

### 10.2 格式与对象

- 完全合成 DOCX 覆盖规格矩阵中的每一语义对象、复杂对象组合和未知对象。
- 标题编号只依据最终语义目录，目录只含批准纯文本标题。
- 图片、表格、公式、字段、批注和修订在允许范围外保持载荷、关系、位置和语义。
- 使用完全合成 DOCX 验证：TOC 更新后目录页数增加或减少；页码位数变化导致目录项换行；正文起始物理页变化但正文逻辑页仍从 1 开始；PAGE/PAGEREF 与 TOC 页码在第 2 轮收敛。
- 目标 Word 验证连续两轮稳定、差异快照完整；模拟三轮仍不稳定时必须进入 blocked_qa，且未收敛结果不得选择性回写基准稿。
- 目标 Word 字段更新、重新打开、重新分页和目录收敛检查通过；LibreOffice/PDF 只作补充，不替代 Word 验收。

### 10.3 长文与恢复

- V0.4.3 先以中等规模合成文档测试对象守恒、批次失败、断点恢复和局部失效。
- V0.4.4 才执行 1000 页和 2000 页完全合成长文测试，并验证内存峰值、阶段耗时、各轮字段更新时间、收敛轮数、最终页数、恢复和幂等性。
- 长文测试不得使用真实书稿，也不得把生成的 DOCX、PDF 或渲染页提交为 CI 工件；只保留无内容的指标摘要。

## 11. CLI 边界

当前命令和未来 `--resume` 只作为内部执行与测试接口。V0.4 不承诺稳定公共 API、安装器、一键封装、命令兼容周期或外部 Agent 的无条件兼容保证。任何对外 CLI、安装方式或一键工作流必须在 V0.4.4 完整能力测试后另建方案，并取得用户单独明确批准。

## 12. 不能宣称的能力

在对应退出条件完成前，不得宣称：

- 已存在正式 `monograph-base` 或“理工科专著” Profile；
- 旧 technical-textbook 已自动兼容或无损迁移；
- 已支持所有出版社、所有表格/图片/公式对象或未知 DOCX 结构；
- 已能可靠处理 1000 页或 2000 页书稿；
- 阶段、抽样、LibreOffice 或 PDF 检查等同于目标 Word 整书验收；
- 当前 CLI 是稳定公共接口或可直接一键安装使用；
- 私有科学符号摘要具有强制法律效力。

## 13. 残余风险

- DOCX 可包含未被现有库暴露的 OOXML、第三方 OLE、损坏关系和厂商扩展，全对象台账的分母定义需要 V0.4.3 以原始包清单交叉验证。
- 规则分层增加解释力，也增加 schema、迁移和 QA 成本；V0.4.1 必须限制可组合机制，避免 Profile 再次复杂化。
- Word 字段更新可能重写非目标 XML；选择性回写和目标 Word 只读复验仍是硬门禁。
- 1000/2000 页视觉检查成本高，自动检测不能完全替代逐页确认；V0.4.4 必须明确人工与自动检查的责任边界。
- 出版社模板、私有符号规范和不同 Word 版本可能互相冲突；没有本任务用户决议时只能阻塞，不能预设统一答案。
- 批次不物理拆分 DOCX，可保护全局关系，但仍可能受 Word 全文重新分页和内存峰值限制。

## 14. 治理与本方案验收

1. 本方案从用户指定并已核对的 `main` 基线创建 `plan/v0.4.0-profile-system`。
2. 方案 PR 只能新增本文件并更新 `docs/plans/INDEX.md`；V0.3.3 及更早方案保持不可变历史快照。
3. PR 不得包含代码、Profile JSON、书稿、私有规范、截图、本地路径、私有哈希或试排成品。
4. QA 必须核对文件范围、旧 Profile 冲突迁移表、后续版本依赖、测试门禁、退出条件、不能宣称的能力和残余风险。
5. PR 保持 Draft。CI 通过后仍须向用户报告 head SHA、文件范围、CI 和风险，并等待明确授权；不得自行转 Ready 或合并。
6. 本方案合并不自动开始 V0.4.1、不发布版本，也不改变当前运行能力。
