# format-monograph V0.4.0：Profile 分层与长文可靠性总体方案

## 1. 定位与范围

V0.4.0 重新划分格式规则的权威来源、Profile 职责和整书完成条件，解决旧 technical-textbook 候选规则同时承担安全、书籍类型、教材功能和任务默认值所造成的冲突，也为千页级 DOCX 的可恢复处理建立统一验收模型。

本方案是后续 V0.4.1 至 V0.4.4 的总体设计，不是实现 PR。本方案不开发代码，不创建正式 Profile，不修改脚本，不发布版本，不封装 CLI，也不宣称已经具备千页级可靠处理能力。

## 2. 格式权威与安全不变量

### 2.1 格式来源优先级

对同一格式属性，运行时按下列顺序从高到低决议：

1. 当前用户对本次任务的明确要求及后续 QA 决定；
2. 用户指定适用于本次任务的出版社要求或 DOCX 模板；
3. 用户选择的书籍类型 Profile；
4. `monograph-base`；
5. GB/T 等标准，仅用于更高层未覆盖项目的补缺。

样书、截图、OCR 和推断只能形成带来源、置信度和确认状态的候选证据，不自动取得上述层级。更高层覆盖较低层时必须记录覆盖链；同层冲突、来源适用关系不明、属性缺失、低置信度或对象无法分类时必须报告并进入 QA，不得静默选择。

### 2.2 独立安全层

安全不变量不属于格式优先级，任何用户要求、模板、Profile 或标准都不能覆盖：

- 不修改作者内容，包括文字、标点、事实、数据、公式语义、题注文字、答案和参考文献内容；只有用户另行明确授权内容编辑时，才建立独立批准范围。
- 不覆盖原稿；所有应用、字段更新、渲染和恢复均操作派生副本。
- 不破坏或静默替换公式、图片、媒体、OLE/MathType、OMML、字段、书签、交叉引用、批注、修订、脚注、尾注、文本框、内容控件及其他嵌入对象。
- 公式保持可编辑；不得把公式栅格化为图片。
- 不绕过内容、结构、字段、目标 Word、逐页视觉、幂等性和恢复审计。
- 无法证明安全时保持原状并报告，不以“格式统一”为理由猜测或删除。

安全层只定义保护、允许变化清单、审计和交付门禁，不提供书籍外观默认值。

## 3. Profile 分层架构

### 3.1 六层模型

| 层级 | 责任 | 允许内容 | 禁止内容 |
| --- | --- | --- | --- |
| 安全层 | 保护原稿、作者内容和复杂对象，限定可变范围及验收门禁 | 内容指纹、对象保护、审计、失败策略 | 版式偏好和可被覆盖的外观值 |
| `monograph-base` | 定义专著共有的语义角色、保守默认和字段顺序 | 角色分类、保持原稿策略、通用目录和审计约束 | 理工科符号细则、教材习题样式、出版社专属值 |
| 书籍类型层 | 定义某类专著的领域排版 | `science-engineering-monograph` 等类型规则 | 安全规则降级、任务特例 |
| 功能模块层 | 按书稿实际对象选择附加能力 | `textbook-pedagogy`、`equation-heavy`、`engineering-drawing`、`code-heavy` | 未选择时自动生效、覆盖更高层来源 |
| 出版社/模板层 | 表达用户指定出版社要求或模板的适用规则 | 可公开的规则摘要、模板映射、来源定位 | 未授权原文、样书内容、本地路径 |
| 任务/用户覆盖层 | 表达当前任务明确要求和 QA 决定 | 属性覆盖、例外对象、批准变更 | 突破安全不变量 |

类型层的正式 ID 为 `science-engineering-monograph`，显示名为“理工科专著”。教材习题、答案和教学提示从类型默认中移出，进入可选 `textbook-pedagogy` 模块；另规划 `equation-heavy`、`engineering-drawing` 和 `code-heavy` 模块。模块只能在用户选择或对象证据充分并经 QA 批准后启用。

### 3.2 扁平化最终 Profile

执行前必须把选定层合成为一个只供本次任务使用的扁平化最终 Profile。每个最终属性至少记录：

- 语义对象、属性和值；
- 最终来源层、来源 ID 和证据摘要；
- 从低到高的候选值与完整覆盖链；
- 冲突类型、处理结果、用户 QA 决定及确认状态；
- 置信度、适用范围和例外对象；
- 是否允许自动应用、仅报告或阻塞执行；
- 安全不变量检查结果。

合成结果不得包含出版社规范全文、私有书稿文字、本地路径或未授权材料。任何未解决冲突、必要属性缺失、低置信度自动规则或无法分类对象，都必须进入冲突/缺失/QA 清单；不得通过数组顺序、最后写入或 Agent 自行判断静默胜出。

## 4. Profile 资产与私有证据边界

- 旧 `technical-textbook-layout*` Profile 全部保留为历史候选及迁移测试输入，不直接改名、删除，也不默认为 `monograph-base` 或“理工科专著”。
- V0.4.2 应从旧候选逐条提取可迁移规则，明确标记为保留、修改、移层、拆分或废弃，并以新 ID 输出；不得让新旧 Profile 同时自动生效。
- 私有科学符号规范只能形成不含原文、本地路径、截图、样书文字或私有哈希的规则摘要，并记录“私有来源、非公开、待任务确认”。
- 私有科学符号规则只允许进入 `science-engineering-monograph`；`monograph-base` 只负责识别、保护和分类科学符号。
- 仓库不得宣称私有符号规范当前具有强制法律效力；GB/T 等标准也只在本方案定义的最低补缺层使用。

## 5. 冻结格式规格矩阵

“归属”表示默认定义该规则的最低层；出版社、模板和当前用户仍可按优先级覆盖，但不得突破安全层。未写明具体值的项目默认保持原稿并报告缺失，不得推断。

| 对象 | 冻结规格 | 归属 | 迁移/确认要求 |
| --- | --- | --- | --- |
| 页面纸张与方向 | 默认保持原 DOCX 各节纸张、方向及既有节边界 | `monograph-base` | 不继承旧比例纸边距作为默认 |
| 页边距与装订 | 默认保持原稿；只有出版社/模板/用户明确值才改 | `monograph-base` | 镜像边距不是无条件默认 |
| 分栏 | 保持原稿，不得自动单栏或双栏 | `monograph-base` | 索引也不强制双栏 |
| 复杂页眉页脚 | 保留原关系、奇偶页、首页不同和横向节结构，按批准规则局部调整 | 安全层 + `monograph-base` | 不批量重建未知布局 |
| 书名 | 建立独立书名角色；具体字体、字号、垂直位置由类型/出版社/任务决定 | `monograph-base` 分类；上层定值 | 不从普通章题样式推断 |
| 序跋/致谢/后记 | 分别识别并保持内容，样式由类型或出版社定义 | `monograph-base` + 类型层 | 不并入普通正文或附录 |
| 摘要 | 独立前置角色，内容不可改，版式由上层决定 | `monograph-base` + 类型层 | 不自动生成摘要 |
| 关键词 | 标签和关键词内容均加粗；其中科学符号仍按语义字形优先 | `science-engineering-monograph` | 不因整体加粗破坏变量正斜体、上下标或公式对象 |
| 目录题名 | “目录”段前 0 pt、段后 18 pt | `science-engineering-monograph` | 题名和 TOC 结果分离建模 |
| 目录项 | 章题项段前 6 pt、段后 0；二至四级项段前后 0 | `science-engineering-monograph` | 具体字号可由出版社/任务覆盖 |
| 目录字段 | 使用真实 Word 动态目录，只收批准语义标题；污染风险时整份切换纯文本 TC | `monograph-base` | 禁止图片、OLE、文本框、表格、空项和重复项 |
| 前置页码 | 前置部分和目录使用阿拉伯数字，从 1 开始 | `science-engineering-monograph` | 替代旧小写罗马数字候选 |
| 正文页码 | 正文独立使用阿拉伯数字，从 1 开始，后续正文节连续 | `science-engineering-monograph` | 不逐章重启 |
| 章首页页眉页码 | 章首页隐藏运行页眉，但保留并显示页码 | `science-engineering-monograph` | 区分页眉可见性与页码可见性 |
| 章题 | 中文黑体；西文/数字 Times New Roman；粗体、居中；不强制新页 | `science-engineering-monograph` | 段前后值可由出版社/任务覆盖 |
| 二级标题 | 中文黑体；西文/数字 Times New Roman；零首行、左、右和悬挂缩进 | `science-engineering-monograph` | 不继承列表缩进 |
| 三级标题 | 中文黑体；西文/数字 Times New Roman；零首行、左、右和悬挂缩进 | `science-engineering-monograph` | 同上 |
| 四级标题 | 中文黑体；西文/数字 Times New Roman；零首行、左、右和悬挂缩进 | `science-engineering-monograph` | 替代旧四级宋体 |
| 标题编号 | 依据最终语义目录重建；只删除获批的旧编号前缀，不改标题文字 | `monograph-base` 机制 + 类型层编号方案 | 歧义前缀阻塞 QA |
| 正文 | 中文宋体、西文 Times New Roman，10.5 pt，两端对齐且末行自然左齐，首行缩进 2 字符，段前后 0，最小 18 pt | `science-engineering-monograph` | 使用 minimum/at-least，不使用固定 18 pt |
| 科学符号 | 按变量、向量、矩阵、单位、上下标、希腊字母等语义决定字形；未知只报告 | `science-engineering-monograph` | 规则摘要不得进入 base，不修改符号内容 |
| 标点 | 默认只报告疑似问题；只有用户明确授权内容编辑才修改 | 安全层 | 格式授权不等于标点编辑授权 |
| 条目与列举 | 识别列表层级并保留文字、编号语义和顺序；具体缩进/间距由上层决定 | `monograph-base` + 类型层 | 不把普通数字段误判为列表 |
| 长引文 | 不因长度自动缩小；仍处于正文语流时继承正文格式 | `monograph-base` | 独立引文样式必须有明确语义或上层要求 |
| 注释体系 | 注释先按脚注、尾注、表注、图注和其他注释分类，再分别应用规则 | `monograph-base` | 未分类注释保持原状并进入 QA |
| 脚注 | 独立角色，保持脚注类型、标记和内容 | `monograph-base`；上层定样式 | 不与尾注、参考文献合并建模 |
| 尾注 | 独立角色，保持尾注类型、标记和内容 | `monograph-base`；上层定样式 | 不自动互换脚注/尾注 |
| 公式 | 保持 OMML、MathType/OLE 等可编辑对象和语义；不得转图片 | 安全层 + `equation-heavy` 可选模块 | 编号和版式依最终类型/任务规则 |
| 图片 | 有意义的原位置、环绕、裁剪和锚点优先保留 | 安全层 + `monograph-base` | 不为统一版式移动图片 |
| 图片默认布局 | 无明确要求且无有意义原布局时，才允许嵌入型、居中、比例缩放 | `monograph-base` | 不自动放大；超出版心缩小仍需保护位置和比例 |
| 图片与图题 | 必须同页；题注后的正文间隔用题注段后 18 pt 表达 | `science-engineering-monograph` | 不插入空白段落制造间隔 |
| 图题/图注 | 图题在图下；内容和既有领域标识不可改，字体与编号由最终 Profile 决定 | `monograph-base` + 类型/模块层 | 工程图纸剖面、节点、详图标识由 `engineering-drawing` 分类 |
| 表格 | 先按语义和拓扑分类，再决定边框、表头、跨页和对齐 | `monograph-base` + 类型/模块层 | 不采用一套通用边框 |
| 表格布局 | 表格位置保持；数据表默认居中、无环绕，例外由原布局或上层规则决定 | `monograph-base` | 不移动表格，不默认首行为表头 |
| 表格边框 | 内容含公式/图片不等于无边框；只有布局容器表默认无边框 | `monograph-base` | 三线表、网格表、图版表分别决议 |
| 表注 | 与表题、表格正文分离建模，内容不可改；位置和样式由上层确定 | `monograph-base` + 类型层 | 不并入参考文献或脚注 |
| 定义/定理/证明 | 分别识别语义角色，保持编号、术语和证明内容 | `science-engineering-monograph` | 无证据时不自动套用强调样式 |
| 例题 | 独立角色，保持题干、解答和编号内容 | `science-engineering-monograph` | 教材化展示由可选模块或上层决定 |
| 习题/答案 | 只格式化已有内容，不推导、补写或改答案 | `textbook-pedagogy` | 未启用模块时保持原稿并报告 |
| 教学提示框 | 不强制转换为单单元格表格，也不默认楷体；优先保留原容器 | `textbook-pedagogy` | 容器转换必须单独批准并审计位置/内容 |
| 代码/算法 | 保持字符、缩进、换行和编号；样式由 `code-heavy` 定义 | `monograph-base` 保护 + `code-heavy` | 不自动改写代码或算法 |
| 参考文献 | 独立角色和规则集合，保持条目内容与顺序 | `monograph-base`；上层定样式 | 不与脚注/尾注共用一个规则 |
| 附录 | 识别并保留已有附录编号和内容；异常编号只报告 | `monograph-base` + 类型层 | 不自动补写或重编号附录 |
| 索引 | 独立角色，保留索引项和字段；不强制双栏 | `monograph-base`；上层定布局 | 栏数保持原稿或由明确要求决定 |
| 术语表 | 独立角色，保持术语及释义内容 | `science-engineering-monograph` | 不自动翻译或增删术语 |
| 缩略语表 | 独立角色，保持缩略语及释义内容 | `science-engineering-monograph` | 不自动展开未知缩略语 |
| 符号表 | 独立角色，科学符号字形按语义优先 | `science-engineering-monograph` | 不自动改符号、单位或含义 |
| 字段更新顺序 | 语义目录 → 标题编号 → 附录/对象序列 → 交叉引用 → 正式目录 → 可选图表目录/索引 → 最终页码 | `monograph-base` | 每章不得重建全书正式目录/分页 |
| 内容保护 | 作者内容和受保护对象零未授权变化 | 安全层 | 失败即拒绝候选结果 |
| 目标 Word 验收 | 用目标 Microsoft Word 更新、重开并验证可编辑字段和版面 | 安全层 | 其他渲染器不能冒充目标 Word |
| 整书视觉 QA | 正式完成前逐页检查全部页面 | 安全层 | 抽样只可用于试排或阶段验收 |
| 幂等性 | 第二次执行不得产生新的非批准变化 | 安全层 | 不通过不得标记整书完成 |
| 恢复 | 从最后一个完整原子检查点恢复，失败批次不得污染已完成批次 | 安全层 + 长文运行层 | 不依赖物理拆分重组 DOCX |

## 6. 旧 technical-textbook 冲突与迁移路径

旧候选只作为迁移输入。V0.4.2 必须逐条生成映射报告，至少落实下表；未列出的旧规则也必须逐项归类，禁止用“兼容旧版”代替迁移决议。

| 旧规则/属性 | 冲突 | V0.4 迁移 |
| --- | --- | --- |
| `FMT-PAGE-301` 镜像比例边距及页眉页脚距离 | 新基线要求纸张、方向、边距、分栏和复杂页眉页脚默认保留 | 只迁移“保留纸张”意图到 `monograph-base`；比例值降为历史证据，只有出版社/任务明确选择时使用 |
| `FMT-BODY-301` 固定 18 pt | 固定行距会裁切图片、公式及高字符 | 在“理工科专著”改为最小 18 pt，其余字体、字号、缩进按冻结正文规则重新建 ID |
| `FMT-HEAD-301` 章题 Arial、段前分页 | 标题西文/数字应为 Times New Roman，章题不强制新页 | 新类型规则改用 Times New Roman，并将 `page_break_before` 设为非默认；出版社/任务可覆盖 |
| `FMT-HEAD-302/303` 西文 Arial | 与统一标题西文字体冲突 | 新类型规则改用 Times New Roman，保留零缩进保护；精确段距单独取证 |
| `FMT-HEAD-304` 四级中文宋体 | 四级标题中文已冻结为黑体 | 迁移为黑体/Times New Roman；旧值仅作回归冲突样本 |
| `FMT-FIELD-301` 宽泛重建和删除手工前缀 | 可能基于错误目录改号或删除标题文字 | 拆为语义目录批准、编号重建和前缀删除三步；只删除获批旧编号前缀 |
| `FMT-TOC-301` 前置小写罗马页码 | 前置部分和目录已冻结为阿拉伯数字 1 起 | 改由“理工科专著”分页规则控制；保留字号等未冻结值为待出版社/任务确认 |
| `FMT-HEADER-301` 章首页隐藏页码 | 新规则只隐藏运行页眉，页码仍显示 | 拆分页眉可见性和页码可见性；页码改为显示 |
| `FMT-CAP-301` 全部题注共用段后 0 及一个通用角色 | 图题后正文需要段后 18 pt，图题、表题、图纸标识和表内文字不能共用一套规则 | 拆分图题、表题、图注和领域标识；保留人工编号与“不自动改号”原则，领域识别移入 `engineering-drawing`，图题后使用段后 18 pt |
| `FMT-TABLE-301` 所有表统一表头、边框和分页假设 | 表格类型和拓扑多样，首行不一定是表头 | 拆为分类、布局保护、边框拓扑、多行表头和跨页策略；未知表阻塞 QA |
| `FMT-NOTE-301` 脚注、尾注、参考文献合并 | 三者语义和格式不同 | 拆为三个独立角色和规则集合，保留“脚注尾注不得互换”安全要求 |
| `FMT-QUOTE-301` 自动 9.5 pt/固定 16 pt | 长引文不得只因长度自动缩小，正文语流应继承正文 | 取消自动套用；只有明确引文语义和上层样式时建立专门规则 |
| `FMT-INDEX-301` 强制双栏和 8 mm 栏距 | 索引不强制双栏 | 栏数/栏距默认保持原稿，明确模板或用户要求才能覆盖 |
| `FMT-ANSWER-301` 答案属于类型默认 | 教材功能不应污染一般理工科专著 | 移入 `textbook-pedagogy`，继续禁止推导或改写答案 |
| `FMT-CALLOUT-301` 单单元格表格和楷体 | 教学提示不强制容器转换或楷体 | 移入 `textbook-pedagogy`；默认保留容器和字体，转换必须单独批准 |
| `FMT-EQ-301/302` 公式保护与版式混合 | 可编辑保护是安全规则，公式密集排版是可选能力 | 可编辑/不栅格化迁入安全层；公式编号和密集排版迁入类型层或 `equation-heavy` |
| `FMT-SECTION-301` 宽表横向分节 | 新基线默认保持页面/分节，不能仅凭宽表自动改变 | 作为经用户确认的任务覆盖候选；无确认只报告，不自动插节 |
| `FMT-TABLE-302` 续表规则 | 可保留，但必须依赖表格语义、真实断点和多行表头 | 迁入表格模块化规则，继续要求已有拆分或明确断点 |
| 旧科学符号候选或私有规范摘要 | 不应进入所有专著基础层 | 只迁入 `science-engineering-monograph`，保留私有来源和非法律强制声明 |

旧 Profile 中不冲突的内容保护、公式可编辑、原稿不覆盖、字段保持可编辑和用户要求最高等原则，也不得直接复制为外观规则：安全内容进入安全层，格式内容重新获得类型/模块归属和来源追踪。

## 7. 确认后的整书处理流程

固定处理顺序如下，后续实现不得重新排序：

1. 确认格式来源与优先级，合成扁平化最终 Profile。
2. 建立最终语义目录和覆盖全文全部对象的台账。
3. 确认页面与分节布局。
4. 处理书名与前置部分。
5. 在同一 DOCX 中按章或对象批次处理。
6. 根据最终语义目录重建标题编号。
7. 处理图、表、公式、注释、附录等对象。
8. 全书统一生成正式目录。
9. 最后更新页码、交叉引用和其他派生字段。
10. 完成内容、结构、字段、目标 Word、逐页视觉、幂等性验收。

每章或对象批次完成后，只更新结构清单、对象状态、保护哈希和原子检查点。不得每章重建全书正式目录或触发全书分页，也不得物理拆分 DOCX 后重新拼接；所有批次始终作用于同一受控工作副本。

## 8. V0.4 长文可靠性模型

### 8.1 全对象台账与覆盖证明

`prepare` 的后续实现必须遍历并登记全部可寻址对象，而不是只记录识别成功对象。对象至少包括文档/分节、段落、标题候选、列表、表格及单元格、图片和绘图、公式和嵌入对象、题注、脚注尾注、字段、书签、交叉引用、批注修订、文本框、内容控件、页眉页脚、附录和后置部分。

每个对象必须且只能处于以下状态之一：

- `approved`：已分类并获准处理，尚待或正在进入格式阶段；
- `formatted`：批准规则已应用且对象级审计通过；
- `unchanged`：明确决定保留原状并完成保护验证；
- `blocked_qa`：缺少决定，保持未改并阻塞相关范围；
- `failed`：处理或验证失败，记录失败原因并隔离。

正式完成前必须证明：

`formatted + unchanged + blocked_qa + failed = 全部对象`

且 `approved` 数量为 0。`blocked_qa` 或 `failed` 可以存在于阶段报告，但存在关键项时不得标记整书完成。台账同时记录规则覆盖率、对象覆盖率、失败原因、未触达对象和分母定义；任何“未处理但未报告”都使验收失败。

### 8.2 批次、检查点与恢复

- 按章或同类对象建立有限批次，每个批次有输入指纹、最终 Profile 指纹、对象集合、前置条件、允许变更、结果和审计摘要。
- 批次提交采用原子检查点：只有应用和对象级审计全部通过才推进检查点；失败时丢弃该批次候选，不污染已完成批次。
- 后续实现支持 `--resume`，从最后一个通过审计的检查点继续；输入、Profile 或上游结构变化时只使依赖批次失效。
- 已完成且依赖未变的批次不得重复处理；恢复过程必须验证检查点链和当前工作副本一致。
- 日志和状态文件只保存结构 ID、状态、规则 ID、非敏感哈希、计数和错误类别，不保存书稿文字或对象载荷。

### 8.3 字段与最终验收

全书字段只在对象格式基本完成后按以下顺序统一处理：

`语义目录 → 标题编号 → 附录/对象序列 → 交叉引用 → 正式目录 → 可选图表目录/索引 → 最终页码`

阶段性批次通过不等于整书完成。未通过目标 Microsoft Word 重新分页和版面检查、整书逐页视觉 QA、内容与对象保护、字段一致性、幂等性和恢复测试时，只能报告具体阶段通过，不得宣称整书已完成或可直接出版。

## 10. 测试门禁

### 10.1 Profile 系统

- 多层同一属性覆盖、同层冲突、缺失属性、低置信度、未分类对象和用户 QA 决议测试。
- 扁平化顺序无关且结果确定；每个最终属性能回溯完整来源和覆盖链。
- 安全不变量无法被任何层覆盖。
- 旧 schema/Profile 只作为显式迁移输入，不会隐式成为新基础层。

### 10.2 格式与对象

- 完全合成 DOCX 覆盖规格矩阵中的每一语义对象、复杂对象组合和未知对象。
- 标题编号只依据最终语义目录，目录只含批准纯文本标题。
- 图片、表格、公式、字段、批注和修订在允许范围外保持载荷、关系、位置和语义。
- 目标 Word 字段更新、重新打开和版面检查通过；其他后端只作补充，不替代 Word 验收。

### 10.3 长文与恢复

- V0.4.3 先以中等规模合成文档测试对象守恒、批次失败、断点恢复和局部失效。
- V0.4.4 才执行 1000 页和 2000 页完全合成长文测试，并验证内存峰值、阶段耗时、字段更新时间、最终页数、恢复和幂等性。
- 长文测试不得使用真实书稿，也不得把生成的 DOCX、PDF 或渲染页提交为 CI 工件；只保留无内容的指标摘要。

## 11. CLI 边界

当前命令和未来 `--resume` 只作为内部执行与测试接口。V0.4 不承诺稳定公共 API、安装器、一键封装、命令兼容周期或外部 Agent 的无条件兼容保证。任何对外 CLI、安装方式或一键工作流必须在 V0.4.4 完整能力测试后另建方案，并取得用户单独明确批准。

## 12. 不能宣称的能力

在对应退出条件完成前，不得宣称：

- 已存在正式 `monograph-base` 或“理工科专著” Profile；
- 旧 technical-textbook 已自动兼容或无损迁移；
- 已支持所有出版社、所有表格/图片/公式对象或未知 DOCX 结构；
- 已能可靠处理 1000 页或 2000 页书稿；
- 阶段、抽样、LibreOffice 或 PDF 检查等同于目标 Word 整书验收；
- 当前 CLI 是稳定公共接口或可直接一键安装使用；
- 私有科学符号摘要具有强制法律效力。

## 13. 残余风险

- DOCX 可包含未被现有库暴露的 OOXML、第三方 OLE、损坏关系和厂商扩展，全对象台账的分母定义需要 V0.4.3 以原始包清单交叉验证。
- 规则分层增加解释力，也增加 schema、迁移和 QA 成本；V0.4.1 必须限制可组合机制，避免 Profile 再次复杂化。
- Word 字段更新可能重写非目标 XML；选择性回写和目标 Word 只读复验仍是硬门禁。
- 1000/2000 页视觉检查成本高，自动检测不能完全替代逐页确认；V0.4.4 必须明确人工与自动检查的责任边界。
- 出版社模板、私有符号规范和不同 Word 版本可能互相冲突；没有本任务用户决议时只能阻塞，不能预设统一答案。
- 批次不物理拆分 DOCX，可保护全局关系，但仍可能受 Word 全文重新分页和内存峰值限制。

## 14. 治理与本方案验收

1. 本方案从用户指定并已核对的 `main` 基线创建 `plan/v0.4.0-profile-system`。
2. 方案 PR 只能新增本文件并更新 `docs/plans/INDEX.md`；V0.3.3 及更早方案保持不可变历史快照。
3. PR 不得包含代码、Profile JSON、书稿、私有规范、截图、本地路径、私有哈希或试排成品。
4. QA 必须核对文件范围、旧 Profile 冲突迁移表、后续版本依赖、测试门禁、退出条件、不能宣称的能力和残余风险。
5. PR 保持 Draft。CI 通过后仍须向用户报告 head SHA、文件范围、CI 和风险，并等待明确授权；不得自行转 Ready 或合并。
6. 本方案合并不自动开始 V0.4.1、不发布版本，也不改变当前运行能力。
