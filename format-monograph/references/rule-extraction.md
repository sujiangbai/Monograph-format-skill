# 规则提取

## 输入登记

为每份资料分配 `SRC-NNN` 编号，记录资料类型、名称、定位信息、摘要和是否允许公开。原件只在用户任务目录中处理。

## 证据优先级

按以下顺序处理当前任务的格式依据：

1. `user_requirement`：当前调用者明确提出的要求及后续 QA 决定。
2. 调用者指定适用的 `written_requirement` 或 `docx_template`。
3. 调用者选择的内置配置。
4. `pdf_specification` 中的 GB/T 默认基础规则。
5. `sample_book`、`image` 和 `text_note`。

明确的高优先级格式要求优先于低优先级依据，同时必须记录冲突。调用者自身要求冲突、资料适用关系不清或触及安全边界时，不得自动裁决，必须写入 `conflicts` 并提出 QA。

调用者的格式优先级不能取消原稿保护、正文内容保护、可编辑公式、字体确认、对象完整性审计和视觉验收。

## 提取步骤

1. 先提取页面、分节、页码和页眉页脚。
2. 再提取前置部分、目录、标题层级和正文节奏。
3. 再提取图、表、公式、题注、字段、注释、参考文献、索引、答案和附录。
4. 将每项要求拆成一条原子规则，不要把多个无关属性放入同一规则。
5. 使用 `FMT-类别-NNN` 编号。
6. 为可由脚本稳定执行的规则标记 `automatic`；其余标记 `manual_review`。
7. 低置信度、缺失单位、缺失适用范围、无法确认的字体、公式图片和含糊静态编号必须进入 QA。
8. 新配置使用 schema `1.1` 并写入 `runtime_policy`；已有 schema `1.0` 配置保持兼容。

## 证据摘要

只写足以支持规则的释义，不复制大段原文，不提交出版社文件、样书、OCR、渲染页或本地路径。

## 批准闸门

配置只有在以下条件同时成立时才能标记为 `approved`：

- 所有拟执行规则均为 `approved`。
- 不存在状态为 `open` 的冲突。
- 不存在未回答的 blocking QA。
- 用户明确确认规则摘要、来源适用关系和派生字段变更范围。
- 所需字体和可编辑公式处理能力已确认。
- 批准人和批准时间已记录。
