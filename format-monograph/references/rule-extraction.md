# 规则提取

## 输入登记

为每份资料分配 `SRC-NNN` 编号，记录资料类型、名称、定位信息、摘要和是否允许公开。原件只在用户任务目录中处理。

## 证据优先级

按以下顺序处理冲突：

1. `written_requirement`
2. `docx_template`
3. `pdf_specification`
4. `sample_book`
5. `image`
6. `text_note`

高优先级资料覆盖低优先级资料，但不要自动解决语义不清或同级冲突。将它们写入 `conflicts` 并提出 QA。

## 提取步骤

1. 先提取页面、分节、页码和页眉页脚。
2. 再提取前置部分、目录、标题层级和正文节奏。
3. 再提取图、表、公式、题注、注释、参考文献和附录。
4. 将每项要求拆成一条原子规则，不要把多个无关属性放入同一规则。
5. 使用 `FMT-类别-NNN` 编号。
6. 为可由脚本稳定执行的规则标记 `automatic`；其余标记 `manual_review`。
7. 低置信度、缺失单位、缺失适用范围或无法确认的字体必须进入 QA。

## 证据摘要

只写足以支持规则的释义，例如“书面规范第 3 页要求一级标题使用黑体三号”。不要复制大段原文，不要将出版社文档嵌入配置。

## 批准闸门

配置只有在以下条件同时成立时才能标记为 `approved`：

- 所有自动规则均为 `approved`。
- 不存在状态为 `open` 的冲突。
- 不存在未回答的 blocking QA。
- 用户明确确认规则摘要。
- 批准人和批准时间已记录。
